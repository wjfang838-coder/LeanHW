Module and integration contract

Module: TopModule.
Ports below are in exact declaration order:
- clk: input 1 bit.
- rst_n: input 1 bit.
- valid_in: input 1 bit.
- data_in: input [7:0].
- valid_out: output 1 bit.
- data_out: output [15:0].

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

Module and ports



Reset

rst_n is an active-low asynchronous reset. Whenever rst_n is low, valid_out is 0 and data_out is 16'h0000, independent of clk, valid_in, and data_in. Reset assertion has priority over all clocked behavior and discards any first byte awaiting its mate. These reset values persist while rst_n is low. Releasing rst_n does not itself change state: valid_out remains 0 and data_out remains 16'h0000 until later rising-edge activity changes them. On the first rising edge after release, the ordinary acceptance law applies: if valid_in is high, data_in becomes the first byte of a new pair; otherwise no byte is accepted. In either case valid_out remains 0 and data_out remains 16'h0000 on that first step because no pair can yet have completed.

At power-up, before rst_n has ever been asserted low, valid_out and data_out are unknown. The implementation must leave both uninitialised, with no initial block or declaration initialiser defining them. Pairing history is also undefined until reset is asserted.

Timing

The active sampling edge is the rising edge of clk. valid_out and data_out are registered outputs. A second accepted byte updates data_out and asserts valid_out for the ensuing cycle, so the result is observed one clock cycle after the row containing that acceptance under the pre-transition observation convention. valid_out is asserted for exactly one cycle. Every rising edge that does not complete a pair makes valid_out low. data_out changes only on reset assertion or pair completion and otherwise holds its previous value.

The evaluated full-cycle trace samples row k before its associated active edge and then applies that rising-edge transition. Thus row k+1 shows the consequences of edge k. Trace rows are observation steps, not implicit 10 ns ticks; the interface supplies no physical clock period or propagation-delay law.

Behaviour

With rst_n high, only a rising edge of clk samples valid_in and data_in and updates the outputs: an accepted first byte begins a pair, an accepted second byte completes it, and any rising edge that does not complete a pair makes valid_out low while data_out holds; falling edges and static clock levels have no effect, repeated transactions follow the same two-acceptance cadence, and asynchronous reset assertion overrides clock activity.

Driving rst_n low asynchronously forces valid_out to 0 and data_out to 16'h0000 and discards any partially collected pair; while low these values persist regardless of clk, valid_in, or data_in, release is inactive until a later rising clk edge, simultaneous assertion has priority, and every assertion restarts pairing from its first byte.

On each rising clk edge with rst_n high, valid_in high accepts data_in and alternately starts then completes successive two-byte transactions, whereas valid_in low accepts nothing, preserves any pending first byte and data_out, and makes valid_out low; uninterrupted high cycles therefore complete a pair every second edge, and reset interrupts and restarts this cadence.

data_in is sampled only on a rising clk edge for which rst_n and valid_in are high; the first accepted sample supplies data_out[15:8] when the next accepted sample supplies data_out[7:0], changes while valid_in is low have no effect, and reset discards any sample awaiting its mate.

rst_n assertion drives valid_out low asynchronously and it remains low through release until clocked operation; because row k is observed before its active edge, a pair completed at edge k is observed as valid_out high in row k+1, the first possible assertion follows the second accepted byte, every non-completing edge clears it, consecutive accepted bytes yield alternating low/high cycles, gaps retain pairing progress but produce low cycles, and reset interruption restarts the sequence.

rst_n assertion drives data_out to 16'h0000 asynchronously and it retains that value through release until a pair completes; because row k is observed before its active edge, completion at edge k is first visible in row k+1 as the first accepted byte concatenated above the second, data_out then holds across first-byte captures and inactive cycles, repeated pairs replace it on their completion edges, and reset interruption clears it and any incomplete pairing history.

All interface quantities are unsigned bit vectors. Because valid_in is one bit, its complete input domain is low or high; data_in may have any value from 8'h00 through 8'hff. Each completed result is exactly {first accepted data_in[7:0], second accepted data_in[7:0]}; there is no arithmetic sign extension or intermediate-width conversion.
