Module and integration contract

Module: TopModule.
Ports below are in exact declaration order:
- clk: input 1 bit.
- rst_n: input 1 bit.
- gray_out: output [3:0].

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

1. Module and ports



2. Reset

rst_n is an asynchronous, active-low reset. As soon as rst_n is asserted low, gray_out is 4'b0000; it remains 4'b0000 while rst_n stays low, regardless of clock edges. Reset has priority if its assertion coincides with a rising edge of clk. Deasserting rst_n alone does not change gray_out. The first rising edge after release retains 4'b0000 and establishes the initial post-reset sequence position; subsequent updates follow the behaviour below.

Before rst_n has ever been asserted low, gray_out is unknown and remains unknown despite clock activity. The implementation must leave that power-up state uninitialised: it must not use an initial block or declaration initialiser to give gray_out a defined value. The sequence position and the indication that reset has been observed are likewise unknown in this interval; assertion of rst_n establishes both at their reset state.

3. Timing

gray_out is registered. While rst_n is high, it changes only as a consequence of a rising edge of clk and holds its value at steady clock levels and on falling edges. With pre-edge sampling, a row associated with a rising edge shows the retained value from before that edge; the result of the edge is visible in the following settled observation. The first rising edge after reset release produces no change from 4'b0000. Thereafter gray_out advances once every two rising edges, so each Gray-code value is held for exactly two clock cycles. A reset assertion changes gray_out asynchronously, without waiting for a clock edge.

The evaluated full-cycle trace uses the interface observation interval: row k is the settled pre-edge observation for full cycle k, followed by that cycle's rising-edge transition. No nanosecond duration is implied by a row because the supplied interface gives neither timing.step_ns nor timing.sample_offset_ns. This observation convention is separate from the circuit law that updates are driven by rising edges and that each sequence value lasts two clock cycles.

4. Behaviour

While rst_n is high, only each rising edge of clk updates gray_out through the modulo-16 reflected-Gray progression (with the first rising edge after reset retaining 4'b0000), whereas a steady clk level and falling edges have no effect; repeated rising edges continue the progression, and a simultaneous low-reset event overrides the clock update and clears gray_out.

rst_n is an asynchronous active-low reset: asserting it immediately clears gray_out to 4'b0000, keeping it low holds that value despite clock edges, deasserting it alone does not change the output, the first subsequent rising edge retains 4'b0000, and any later assertion interrupts and restarts the sequence with reset taking priority over a simultaneous rising edge.

With pre-edge row sampling, a row at a rising edge still shows the previously retained gray_out and the edge's result is observable only afterward: asynchronous reset assertion yields 4'b0000 immediately, reset release retains zero, the first post-release rising edge still produces zero, later rising edges produce the cyclic reflected-Gray sequence for modulo-16 counts, and gray_out holds between edges until reset or the next rising-edge update.

For sequence index n, gray_out = G(n) = n ^ (n >> 1), with n interpreted as an unsigned 4-bit value and advanced modulo 16. The complete cyclic sequence is 0000, 0001, 0011, 0010, 0110, 0111, 0101, 0100, 1100, 1101, 1111, 1110, 1010, 1011, 1001, 1000, then 0000 again. Thus the value after the Gray code for binary count 15, 4'b1000, is the Gray code for count 0, 4'b0000. Each listed value is retained for two rising-edge clock cycles, including the initial zero after reset.

If reset is asserted during counting, any pending cadence phase and sequence progress are cancelled immediately. Release starts again from 0000 under the first-edge-retains-zero rule. There are no transaction-start or disabled-operation inputs other than reset, no completion pulse, and no separate result-valid output. Once reset has established a defined value, gray_out retains its last defined result between effective updates.
