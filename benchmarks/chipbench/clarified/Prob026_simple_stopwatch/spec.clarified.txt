Module and integration contract

Module: TopModule.
Ports below are in exact declaration order:
- clk: input 1 bit.
- rst_n: input 1 bit.
- second: output [5:0].
- minute: output [5:0].

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

1. Module and ports



3. Reset

Reset `rst_n` is active low and asynchronous. Whenever `rst_n` is low, `second` and `minute` read 0 immediately, and every rising edge while it remains low keeps both values at 0. Deasserting `rst_n` has no immediate effect. On the first rising edge after release, `second` advances from 0 to 1 and `minute` remains 0; because observation precedes the active edge, the values immediately before that edge are still 0 and 0.

At power-up, before `rst_n` has ever been asserted low, both `second` and `minute` are unknown. They remain unknown through rising edges until reset is asserted. The implementation must leave both stored values uninitialised in that interval, with no initial block or declaration initialiser that gives either one a defined value.

4. Timing

Both outputs are registered and update only just after a rising edge of `clk`, except that assertion of asynchronous reset changes both outputs immediately. A sampled row observes the pre-edge output values; the effects of that row's rising edge first appear in the next row. Each full-cycle row is separated by the interface `timing.step_ns`, and row k denotes k times `timing.step_ns` after settling, sampled at `timing.sample_offset_ns`. This is only the trace observation convention. The circuit's actual clock period and propagation delays are not fixed by this specification.

`second` has one-edge state-update latency from its own pre-edge value and the pre-edge value of `minute`. `minute` has one-edge state-update latency from the pre-edge value of `second`. There are no pulse or independently periodic output signals.

5. Behaviour

On every rising edge with `rst_n` high and defined stored values, apply these laws to the pre-edge values:

- If `second` is 60, `second` becomes 1 and `minute` increments modulo 64.
- Otherwise, if `minute` is 60, both outputs hold their prior values.
- Otherwise, `second` increments modulo 64 and `minute` holds its prior value.

Thus the `second = 60` rollover has priority when both values are 60. Every other encoding of each six-bit value is covered by the rules above. Repeated rising edges repeatedly apply the same rules. Falling edges and stable levels of `clk` have no effect. An intervening low assertion of `rst_n` immediately clears both outputs; if reset assertion coincides with a rising edge, reset takes priority. Releasing reset does not itself change either output, and counting resumes on the next rising edge.
