Module and integration contract

Module: TopModule.
Ports below are in exact declaration order:
- rst_n: input 1 bit.
- clk: input 1 bit.
- pass_request: input 1 bit.
- clock: output [7:0].
- red: output 1 bit.
- yellow: output 1 bit.

Public parameters (preserve names, defaults and symbolic port ranges):
-  idle: default = 2'd0.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

1. Module and ports.



3. Reset.

rst_n is an active-low asynchronous reset and has priority over a simultaneous rising edge and over pass_request. While rst_n is low, clock is 8'd10 and red, yellow, and green are all 1'b0. Continued or repeated reset assertion retains those values. Reset deassertion alone changes nothing.

After reset is released, the first completed rising edge changes clock from 8'd10 to 8'd9 and retains all three lights low. The second changes clock to 8'd8 and again retains all three lights low. The third reloads clock to 8'd10 and makes red 1'b1 while yellow and green remain 1'b0.

At power-up before rst_n has ever been asserted low, clock, red, yellow, and green are all unknown. They must remain uninitialised in that interval: no initial value or declaration initialiser may define them.

Before reset, the stored light interval, countdown, delayed interval, and three stored light values are invalid; the startup-edge count is zero. Reset establishes interval encoding 0, countdown 8'd10, delayed-interval encoding 0, stored red/yellow/green values of 1'b0/1'b0/1'b0, and a startup-edge count of zero. Reset assertion or continued assertion restores exactly these values.

4. Timing.

All sequential changes occur only on a rising edge of clk while rst_n is high. Static clock levels and falling edges have no effect. Asynchronous reset assertion takes effect without waiting for an edge. A pre-edge observation contains the old values; the observation after a completed rising edge contains that edge's updates. In the evaluated full-cycle trace, row k is the settled observation before active edge k, and adjacent rows are separated by one full clock cycle; this observation convention is separate from the circuit's cycle-counted delay laws.

clock is an eight-bit registered output. An effective rising edge normally changes it to its previous value minus one modulo 256. A qualifying pass_request changes it to 8'd10 on that edge instead. The edge on which a delayed light change becomes visible reloads it to 8'd10 for red, 8'd60 for green, or 8'd5 for yellow, except that a qualifying pass_request has priority.

red, yellow, and green are registered outputs. A light-interval transition is initiated by a rising edge whose pre-edge clock value is 8'd3. The new one-hot light value becomes visible after two further rising edges have completed, and its countdown reload occurs on that same edge. Thus the represented terminal observations after the initiating edge are 8'd2 and then 8'd1 before the new light and its reload become visible. Each light remains asserted throughout its own interval and deasserted otherwise. The normal visible countdown spans are red 10 through 1, green 60 through 1, and yellow 5 through 1, one count per completed rising edge unless the pedestrian law changes green's count.

5. Behaviour.

After startup, the light intervals repeat red, green, yellow, red. Exactly one light is asserted after red first becomes visible. Transition initiation at clock 8'd3 does not immediately change a light output: the prior light remains asserted for the observations at clock 8'd2 and 8'd1, and the next light becomes asserted with its reload on the following observation.

On any rising edge with rst_n high, pass_request affects the next clock value only if green is currently 1'b1 and the pre-edge clock value is greater than 8'd10. In that case the next clock value is 8'd10. If pass_request is low, green is low, clock is at or below 8'd10, or no rising edge occurs, pass_request has no effect. Repeated qualifying requests each select 8'd10; once the pre-edge value is 8'd10 or less, the request no longer qualifies. Reset has priority. pass_request never directly changes red, yellow, or green.

With rst_n high, each rising edge advances the countdown and the delayed light sequence exactly once. Repeated rising edges repeat the update applicable to each successive pre-edge state. The eight-bit decrement wraps modulo 256 for every otherwise reachable encoding. The two-bit interval encoding uses 0 for red, 1 for green, and 2 for yellow. Encoding 3 drives all three lights low when it reaches the visible stage; on a pre-edge clock value of 8'd3 its next interval is encoding 0, and a change into visible encoding 3 reloads clock to 8'd5. This fully specifies all stored encodings.

The reset and power-up laws apply independently of clk and pass_request. The countdown-terminal law applies identically at the end of every represented light interval: a pre-edge clock value of 8'd3 produces a next observation of 8'd2, not an immediate reload.
