I would like you to implement a module named TopModule with the following
interface. All input and output ports are one bit unless otherwise
specified.

 - input  clk
 - input  rst_n
 - input  A (8 bits)
 - input  B (8 bits)
 - input  vld_in
 - output lcm_out (16 bits)
 - output mcd_out (8 bits)
 - output vld_out

Design a sequential circuit that takes two unsigned numbers as input and
outputs their least common multiple (LCM) and greatest common divisor (GCD).
The bit width can be determined by parameter DATA_W. For this implementation,
DATA_W is 8, so A, B, and mcd_out are 8 bits while lcm_out is 16 bits.

The circuit should operate as follows:
- When vld_in is asserted, the input data A and B are valid and should be
  processed
- The circuit computes both the LCM and GCD of the two input numbers
- When the computation is complete, vld_out should be asserted to indicate
  that the output data is valid
- The rst_n signal is an active-low reset signal

Assume all sequential logic is triggered on the positive edge of the clock.

Clarification: After the iterative reduction detects A==B, the FSM spends one additional dedicated Finish cycle in which the result output is latched to the converged value and vld_out is pulsed high for exactly that one cycle - the result and the valid pulse appear one clock cycle after equality is reached, not in the same cycle.


Explicit local benchmark revision: zero arithmetic and Finish timing (v1).
The original text above is retained except for the individually scoped amendments below. This is a corrected benchmark, not an unchanged upstream problem.

LB1 (zero results): The unsigned-number LCM/GCD promise includes zero operands. An accepted (0,b) or (a,0) returns LCM=0 and GCD equal to the nonzero operand. For (0,0), this revised benchmark explicitly defines both results as zero. These requests complete; subtracting zero indefinitely is not permitted. For either zero case, accepting edge E0 captures the operands, E1 enters the dedicated Finish interval, and E2 publishes the numeric result and one-cycle vld_out=1. The zero bypass must not change positive-operand reduction behavior.

LB2 (the final clarification's equality/Finish timing): The original phrase "the result and the valid pulse appear one clock cycle after equality is reached" is replaced by this precise edge law. For positive operands, each reduction edge performs at most one subtraction. If equality first becomes true immediately after edge R, the next edge R+1 detects that pre-edge equality and enters Finish; edge R+2 latches GCD to the converged value, publishes LCM=A*B/GCD, and raises vld_out for exactly one interval. If the accepted positive operands are already equal, R is E0, so completion is E2. "Result output latched to the converged value" refers to mcd_out; lcm_out is the mathematical LCM, not the GCD. This replaces only the ambiguous equality/publication phrase and singular-output interpretation.

LB3 (parameter family): DATA_W is a positive integer, default 8; A, B and mcd_out have DATA_W bits and lcm_out has 2*DATA_W bits. The three public integral encoding parameters IDLE=0, lcm1=1 and Finish=2 may be overridden to pairwise distinct integer values in 0..3. This explicit domain matches the two-bit state storage; it is not an assumption inferred by a candidate. All unsigned input encodings, including zero, remain supported.
