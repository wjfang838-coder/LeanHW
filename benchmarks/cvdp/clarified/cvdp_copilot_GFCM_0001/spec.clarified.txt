# Glitch-Free Clock Switching (MUX) RTL Design Specification

### Objective:
Design an RTL module `glitch_free_mux` that switches between two input clock signals (`clk1` and `clk2`) based on a select input signal (`sel`). The output clock (`clkout`) must switch glitch-free. When `sel = 0`, the output clock should be `clk1`; when `sel = 1`, the output clock should be `clk2`. The transition between clocks must happen smoothly without any glitches. `rst_n` is asynchronous active-low reset input signal. When `rst_n` is asserted (`rst_n = 0`), `clkout` should be driven low.

## Requirements
1. **Glitch-Free Switching**:
   - The output clock (`clkout`) must switch between `clk1` and `clk2` without any glitches. 
   - Assume that clk1 and clk2 are synchronous clocks. (Synchronous clocks have a predictable, consistent phase difference.)
     - The waveform below shows examples of synchronous clocks with a fixed phase difference.
     - `T` represents the fixed phase difference between `clk1` and `clk2`.
     - `T` can be any value, as long as the minimum time between launching and capturing edges are greater than the maximum combinational delay between time arcs between `clk1` and `clk2`

   - The `sel` signal is assumed to be driven by one of the two input clock sources (clk1 or clk2). It is synchronous to one of the input clocks.
   - For a request selecting clk2 that remains current, clk1 is disabled on its first subsequent positive edge, then clk2 is enabled on its first positive edge strictly after that disable event.
   - For a request selecting clk1 that remains current, clk2 is disabled on its first subsequent positive edge, then clk1 is enabled on its first positive edge strictly after that disable event. A new sel change supersedes every uncompleted action for the older request: only the latest selection is pending. If selection returns to the still-enabled clock before disable, the pending switch is cancelled. During the all-disabled interval the latest selection determines which clock may next be enabled. Simultaneous disable and target-clock edges perform disable only; enable waits for a later target-clock edge. Reset cancels pending requests and disables both outputs; after release the selected clock is enabled on its first subsequent rising edge.

1. Module and ports

The module name is glitch_free_mux. The public inputs are clk1, clk2, sel and rst_n, each one bit. The public output is clkout, one bit. No public parameters are documented. This enumeration is not a normative declaration order: Q9 confirms the names and directions but explicitly leaves positional declaration order unverified. Named wiring is portable consumer guidance. 3. Reset

rst_n is asynchronous and active low. Assertion, independently of either clock edge, disables both clock paths, cancels pending switching, and drives clkout low. Assertion dominates simultaneous clock or selection events. Throughout assertion both paths remain disabled and clkout remains zero. Selection during reset does not enable a path. Release alone leaves both disabled and clkout zero; the latest selected clock is enabled on its first subsequent rising edge. Its high level is then visible at clkout after settling. Subsequent falling and rising levels follow that clock until a switching disable or reset assertion.

Implementation choice C1: at power-up before any reset, both clock paths are disabled, with no pending request, and clkout is zero. The first subsequent rising edge of the currently selected clock enables that path. This is a compatible concrete initialization decision, not a source-derived hardware power-up guarantee. No mandatory reset or warm-up is imposed. The finite model starts directly in this chosen state, not in an assumed post-reset setup. Its initial clock-history observation establishes the current levels without inventing an edge. The history fields are observation bookkeeping rather than additional hardware storage obligations.

4. Timing

clkout follows the enabled clock's current level combinationally after settling; when neither path is enabled it is zero. Clock-path changes occur on the rising edges specified below, with no additional publication register or extra physical edge. No absolute clock period, duty-cycle count, propagation delay, or uniform switching latency in cycles is specified: these belong to the supplied input clocks and their phase relationship. The output's ordinary high and low intervals follow those of the enabled input clock. The disabled interval is determined by the disable edge and the later eligible target edge, not a fixed timeout.

For a held request selecting the other clock, E0 is the selection change; E1 is the enabled clock's first rising edge strictly subsequent to E0; E2 is the selected target clock's first rising edge strictly after E1. Before E1 the old clock continues to determine clkout. Immediately after E1 both paths are disabled and clkout is zero. Immediately after E2 the target is enabled and clkout follows it. Simultaneous source-disable and target rising edges perform disable only; the target must wait for a later rising edge. No fixed number of completed cycles is added between E1 and E2.

From reset assertion through release, clkout is zero. Release is not a publication event. A rising edge simultaneous with release does not enable either path: clkout remains zero after that event. At the first strictly subsequent selected rising edge clkout becomes that clock's high level; at its next falling edge it becomes low. With selection held, the second and third selected rising edges similarly publish high levels, and their falling edges publish low levels. A rising edge of the other clock alone does not enable it.

Observation convention: this finite half-cycle model receives explicit clock levels and reset levels. Each row observes the settled output of the pending level/edge transition; the same transition is then committed exactly once. It includes assertion/release observations and does not identify a row with an implicit 10 ns tick. iface.json supplies neither timing.step_ns nor timing.sample_offset_ns; no numerical spacing or sampling offset is asserted here. This observation convention is separate from the circuit's actual period and delay laws. The represented scenario requires observations of each relevant level transition; it does not prove behavior for unobserved physical events. Full asynchronous reset obligations, including pulses between clock edges, remain circuit requirements.

5. Behaviour

While clk1 is enabled, clkout follows clk1 at both levels; a held request for clk2 disables clk1 on its first subsequent rising edge.

While clk2 is enabled, clkout follows clk2 at both levels; a held request for clk1 disables clk2 on its first subsequent rising edge.

Every new sel change supersedes uncompleted actions for the older request; returning to the still-enabled clock before disable cancels the pending switch.

During an already all-disabled interval, the latest selection determines the eligible clock, and its first rising edge after the prior disable or reset release enables it even if selection changes at that edge.

Asynchronous active-low reset cancels pending requests, disables both paths and forces clkout to zero; release alone does not enable a path.

clkout is zero with both paths disabled and otherwise follows the enabled clock, with disable and enable published after their specified rising-edge events without another physical edge.

The input-clock synchronism, fixed predictable phase relationship, phase-separation timing condition, and sel synchronism assumptions in the retained original remain requirements. The two binary selections exhaust the one-bit selector's defined encodings. An unselected clock still supplies a possible future enabling edge, but its levels do not contribute to clkout while its path is disabled. Stable selection permits indefinite clock propagation; completed switches may repeat without reset. Reset can interrupt any switch and establishes a fresh all-disabled state.

When sel changes simultaneously with the currently enabled clock's rising edge, that edge is not subsequent to the new request and does not disable the enabled clock. The latest request supersedes the older pending request, including cancellation if it selects the still-enabled clock. If the latest request continues to select the other clock, disable occurs on the first later rising edge of the enabled clock, and enable occurs on the selected clock's first rising edge strictly after disable. This follows the original subsequent-edge and supersession requirements; it is not an amendment or an answer-derived law. Q2–Q8 remain unclear and supply no certain supplemental laws or hardware unknown authorization.
