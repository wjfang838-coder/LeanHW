Design an **8-bit barrel shifter** which can shift the bits of an 8-bit input either to the left or to the right based on a control signal. This shift can range from 0 to 7 bits, as specified by another control signal. The operation must complete in **one clock cycle**. The detailed design specification for the **8-bit barrel shifter** is given below :

## Design Specification:

A **barrel shifter** is a digital circuit that shifts a data word by a specified number of bits in one clock cycle. It is commonly used in digital systems like microprocessors to perform rapid shifts of binary numbers, which is useful in operations such as multiplication, division, and data manipulation.

### Module Name:
`barrel_shifter_8bit`

### Key Considerations:
This design should be a **combinational logic**. The output must change immediately based on the input and control signals

### Interface:

#### Inputs:
- **`data_in`** (8-bits, [7:0]): The 8-bit input data. This will be shifted by a number of bits based on the other control signals.
- **`shift_bits`** (3-bits, [2:0]): Determines how many bits to shift the input. This value can range from `3'b000` (no shift) to `3'b111` (7-bit shift).
- **`left_right`** (1-bit): Decides the direction of the shift.
   - `left_right = 1`: Shift left.
   - `left_right = 0`: Shift right.

#### Output:
- **`data_out`** (8-bits, [7:0]): The result after shifting the input. The output can range from 8'b00000000 to 8'b11111111.

### Behavior and Data Flow:
The input data (`data_in`) undergoes a shift operation, either to the left or right, as determined by the `shift_bits` value and the direction indicated by `left_right`. When `data_in` shifts right by the number specified in `shift_bits`, zeros are inserted into the Most Significant Bit (MSB) positions, equal to the value of `shift_bits`. Conversely, when `data_in` shifts left by the `shift_bits` value, zeros are inserted into the Least Significant Bit (LSB) positions, also corresponding in number to `shift_bits`.

### Example Operations:

#### Left Shift Example:
- `data_in` = 8'b11001100, `shift_bits` = 3'b100, `left_right` = 1  
- `data_out` = 8'b11001100 << 4 = 8'b11000000  

#### Right Shift Example:
- `data_in` = 8'b11001100, `shift_bits` = 3'b100, `left_right` = 0  
- `data_out` = 8'b11001100 >> 4 = 8'b00001100

3. Reset.

There is no reset port, reset operation, or stored state. Reset polarity, assertion, release, reset edges, and first-step-after-release behavior are therefore inapplicable. At power-up, before any input change, data_out is already the combinational result of the current values of data_in, shift_bits, and left_right. It is neither a stored initialization value nor unconstrained.

4. Timing.

data_out is combinational with zero clock-cycle latency. It continuously reflects the current data_in, shift_bits, and left_right in the same combinational phase. There is no clock or other cycle-boundary input, capture edge, registered latency, pulse, periodic output, hold or clear interval, completion event, or restart event.

For the evaluated model trace, row k is the kth settled-input observation and samples the combinational output for that row's inputs before the identity state transition. The interface specifies neither timing.step_ns nor timing.sample_offset_ns, so row indices do not establish a physical clock period, propagation delay, or implicit 10 ns interval. This table observation convention is separate from the circuit law of immediate combinational response.

5. Behaviour.

For every data_in value, data_out is the low eight bits of data_in shifted by shift_bits—left when left_right is 1 and logically right when left_right is 0—and any data_in change, including one simultaneous with either control change or following any prior combination, immediately recomputes the result from the current inputs with no inactive level, capture, interruption, or transaction history.

For every legal shift_bits value from 3'b000 through 3'b111, data_out is data_in shifted by that unsigned count—left with eight-bit truncation when left_right is 1 and logically right when left_right is 0—and any shift_bits change, including one simultaneous with another input change or following any prior combination, immediately recomputes the result with no inactive level, capture, interruption, or transaction history.

left_right selects the shift direction for the current data_in and shift_bits, with 1 selecting an eight-bit-truncated left shift and 0 selecting a logical right shift, and a selector change, whether isolated, simultaneous with another input change, or following any prior combination, immediately selects the newly requested result with neither level inactive and no capture, interruption, or transaction history.

data_out continuously equals the low eight bits of data_in shifted left by shift_bits when left_right is 1 or logically right by shift_bits when left_right is 0, so there is no reset assertion or release, capture edge, first-result latency, hold or clear interval, completion, or restart; because the interface has no active edge, pre-edge row-k sampling and capture-to-observation latency are inapplicable and every input change produces the corresponding output in the same combinational phase.

Both operands are unsigned. Before shifting, data_in is interpreted at its specified eight-bit width. shift_bits is interpreted as its unsigned three-bit value, so its complete domain is 0 through 7. A left shift is evaluated with sufficient expression width to retain shifted bits until the documented result boundary, and truncation occurs at assignment to the eight-bit data_out; equivalently, data_out receives the low eight bits of the mathematical left-shift result. A logical right shift inserts zeros at the most-significant side. A left shift inserts zeros at the least-significant side. A shift count of zero leaves the eight-bit input unchanged.

left_right is exactly one bit, so its complete domain is 0 and 1 and there are no other encodings. The function is stateless and has no enable or transaction protocol; consequently there are no disabled modes, cancellations, starts, repeated transactions, retained results, or terminal modes.
