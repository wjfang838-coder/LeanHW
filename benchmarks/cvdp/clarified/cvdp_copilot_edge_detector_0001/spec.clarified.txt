1. Module and ports.

The module name is sync_pos_neg_edge_detector. It has no source-specified public parameters.

The complete interface consists of these scalar, one-bit ports: input i_clk; input i_rstb; input i_detection_signal; output o_positive_edge_detected; output o_negative_edge_detected. Q10 confirms these exact names and directions and requires connections by name. Neither the source nor Q10 verifies positional declaration order, so the displayed enumeration is not a normative positional order; the module must be instantiated by name.

3. Reset.

i_rstb is an active-low asynchronous reset. Whenever i_rstb is low, o_positive_edge_detected and o_negative_edge_detected are both 0 and every edge-detection state element is cleared immediately, without waiting for a rising edge of i_clk. Reset takes priority over edge detection. When i_rstb is deasserted, normal edge detection resumes.

Clearing the edge-detection state sets the remembered input sample and both registered detection results to 0. Consequently, on the first rising edge after reset release, a sampled i_detection_signal value of 1 produces a positive-edge indication for the following clock cycle, while a sampled value of 0 leaves both indications at 0.

The source specifies no hardware power-up value before reset has ever been asserted. Only results that still depend on such uninitialized state are unspecified: initially the outputs have no specified value, and the first rising-edge comparison without prior reset may depend on an unspecified remembered sample. A rising edge nevertheless records the current input and replaces both result registers; after that capture, subsequent comparisons obey the complete behavior below. In particular, lack of prior reset does not make later behavior perpetually unconstrained, does not require X to be driven, and does not impose a reset-before-use restriction.

For the concrete worked-trace model only, each stimulus starts in the state reached by asserting i_rstb low long enough for its asynchronous action to clear the remembered sample and both results to 0, then releasing it as applicable to the listed stimulus. Every modeled initial value follows from that reset action. This finite verification setup is separate from the RTL power-up contract and adds neither a reset-before-use restriction nor a hardware power-up guarantee.

4. Timing.

i_clk is active on its rising edge. With reset released, i_detection_signal is captured at every rising edge. Both outputs are registered. Each is updated by that capture and is visible after the capture edge for the following clock cycle; before the capture edge it retains the result from the preceding capture. An asserted detection output lasts exactly one clock cycle because the next rising edge replaces it with the result of the next comparison. Neither output is periodic.

A rising transition presented after an active rising edge does not assert o_positive_edge_detected until the next rising edge captures that transition. A falling transition presented after an active rising edge does not assert o_negative_edge_detected before the next rising edge captures that transition; the asserted sample occurs after that capture edge.

The concrete model uses a full-cycle, pre-transition observation convention: row k first samples the outputs from state s[k] and the row's inputs, then the represented rising edge computes s[k+1]. The interface gives no numeric timing.step_ns or timing.sample_offset_ns, so no physical-time spacing is specified and row k does not imply a 10 ns tick. This table convention is separate from the circuit's rising-edge capture and one-cycle pulse laws.

5. Behaviour.

i_detection_signal is a one-bit, glitch-free, debounced input. No additional debouncing behavior is required.

With reset released, every rising edge compares the captured i_detection_signal value with the value captured at the preceding rising edge. If the preceding value is 0 and the current value is 1, o_positive_edge_detected becomes 1 and o_negative_edge_detected becomes 0 for the following clock cycle. If the preceding value is 1 and the current value is 0, o_positive_edge_detected becomes 0 and o_negative_edge_detected becomes 1 for the following clock cycle. If the two values are equal, both outputs become 0 for the following clock cycle. The current value becomes the remembered value for the next capture.

Repeated stable samples therefore produce 0 on both outputs. Opposite transitions captured on successive rising edges produce successive one-cycle indications of the corresponding polarity. Simultaneous positive and negative indications cannot result from a transition of this one-bit input. Assertion of i_rstb at any time immediately cancels any indication, clears the remembered sample and both results to 0, and holds both outputs at 0. Release of i_rstb resumes the ordinary rising-edge rule, including repeatedly after interrupted operation.

The harness evidence for i_clk establishes rising edges as capture events and falling edges as observations; it does not establish additional laws for static-clock or coincident-event cases. The source-supported active-low asynchronous reset law governs reset assertion, priority, interruption, repetition, and release despite the narrower harness observations. With reset released, a 0-to-1 value held across a rising capture edge produces o_positive_edge_detected = 1 after that edge, and a 1-to-0 value held across a rising capture edge produces o_negative_edge_detected = 1 after that edge; the next capture replaces each pulse according to the next comparison. The positive output is the registered one-cycle result of each rising-edge comparison, including the source-defined reset and restart behavior. The negative output is the registered one-cycle result of each rising-edge comparison, including the source-defined reset and restart behavior.
