Design a 32-bit Fibonacci series generator that updates the value at each clock cycle. The generator will compute the next Fibonacci number based on the sum of the two preceding numbers and store them in registers.

## Design Specification:

The fibonacci_series module generates a 32-bit Fibonacci sequence, starting from F(0) = 0 and F(1) = 1. Each Fibonacci number is computed by summing the two preceding values, updating at every rising edge of the clock. When the sum of the next Fibonacci number exceeds 32 bits, the module detects overflow and sets the `overflow_flag` after one clock cycle to propagate the last Fibonacci number to the output, after which it automatically restarts the sequence from F(0) and F(1).

### Module Name
The module is named `fibonacci_series`, accurately describing its function of generating Fibonacci numbers while handling overflow.

### Key Considerations

**Sequential Fibonacci Calculation**: Each Fibonacci number is generated by summing two previous numbers, stored in `RegA` (F(n-2)) and `RegB` (F(n-1)).

**Synchronous Operation**: All calculations and updates are synchronized with the positive edge of the clock (`clk`).

**Overflow Detection and Sequence Reset**: The module detects overflow when a computed Fibonacci number exceeds 32 bits. If overflow is detected, the `overflow_flag` is set on the next clock cycle to propagate the final Fibonacci number to the output, and the sequence restarts from its initial values, F(0) and F(1).

## Interface

### Inputs:

- `clk`: The clock signal to synchronize Fibonacci generation, initiating a new calculation on each rising edge.

- `rst`: An active-high reset signal. When asserted, it resets the sequence to F(0) = 0 and F(1) = 1, clearing the `overflow_flag`.

### Outputs:

- `fib_out`: A 32-bit output that holds the current Fibonacci number, updated at each clock cycle.

- `overflow_flag`: A signal that is set high one cycle after overflow is detected. It remains high until reset or until the sequence automatically restarts after overflow.

## Behavior and Data Flow

### Reset Behavior (rst = 1):

When `rst` is asserted: 

- `RegA` is initialized to 0 (F(0)), and `RegB` is initialized to 1 (F(1)).
- `fib_out` is set to 0, representing F(0).
- `overflow_flag` is cleared to 0, indicating no overflow.

### Fibonacci Sequence Generation (rst = 0):

With `rst` low, Fibonacci sequence generation proceeds.

On each rising clock edge:

- **Next Fibonacci Calculation**: `next_fib` = `RegA` + `RegB`

- **Overflow Detection**: If `next_fib` exceeds 32 bits (`next_fib[32]` == 1), `overflow_flag` is set to 1.

- **Register Updates**: If `next_fib` exceeds 32 bits (`next_fib[32]` == 1), `overflow_detected` is set to 1, indicating overflow. On the following clock cycle, this triggers a reset and sets the `overflow_flag`.

- **Output Update**: `fib_out` is updated with the current value in `RegB`.

## Example Operations

**Initial State** (after reset):
`RegA` = 0, `RegB` = 1, `fib_out` = 0, `overflow_flag` = 0

**Clock Cycle 1**:
F(2) = 1 + 0 = 1

After the clock edge, `RegA` = 1, `RegB` = 1, `fib_out` = 1, `overflow_flag` = 0

**Clock Cycle 2**:
F(3) = 1 + 1 = 2

After the clock edge, `RegA` = 1, `RegB` = 2, `fib_out` = 2, `overflow_flag` = 0

**Overflow Condition**:

When `next_fib[32]` is set, `overflow_detected` is set to 1, and `RegB` final Fibonacci value is assigned to `fib_out`. On the next clock cycle, `overflow_flag` is set to 1, `fib_out` resets to 0, and the sequence restarts with `RegA` = 0 and `RegB` = 1.

1. Module and ports.



3. Reset.

rst is active high. Its physical rising assertion is asynchronous: immediately after assertion, RegA is 32'h00000000, RegB is 32'h00000001, fib_out is 32'h00000000, overflow_flag is 0, and any pending overflow or restart phase is cleared. Reset has priority over a simultaneous clk rising edge. Every clk rising edge while rst is high reapplies these values. Deassertion has no immediate effect. On the first clk rising edge after release, fib_out becomes 32'h00000001, the sequence pair advances, and overflow_flag remains 0.

Before the first physical rst assertion, fib_out and overflow_flag are hardware-unknown. This scope ends immediately upon the first assertion, even if ordinary clk edges occurred beforehand. It imposes no reset-before-use input restriction and makes no initialized power-up guarantee.

Amendment A1 (Q198, reset assertion sensitivity). The exact original clause “**Synchronous Operation**: All calculations and updates are synchronized with the positive edge of the clock (`clk`).” is superseded only insofar as it describes physical reset assertion. The certain answer law states exactly: “rst has asynchronous assertion kind.” Fibonacci calculation, publication, overflow detection, automatic restart, and held-reset clock-edge behavior remain rising-edge operations.

4. Timing.

fib_out and overflow_flag are registered. Only clk rising edges perform ordinary advancement; a static clock level and a falling edge have no effect. Asynchronous rst assertion is the sole exception, and rst release is not an update event.

Define E0 as physical rst assertion. After release, define E1, E2, and E3 as the first three clk rising edges. Immediately after them, fib_out is respectively 32'h00000001, 32'h00000001, and 32'h00000002. Each post-edge publication uses the sequence operands from before that edge; simultaneous advancement of the pair does not select the published value.

Define D as the rising edge whose unsigned 33-bit sum of the two pre-edge 32-bit terms has bit 32 set. Immediately after D, fib_out is 32'hb11924e1 and overflow_flag is 1. After one completed clock interval, R is the immediately following rising edge; immediately after R, fib_out is zero, the starting pair is restored, and overflow_flag remains 1. After one further completed interval, the next rising edge publishes fib_out=1 and clears overflow_flag to 0. The high pulse therefore spans exactly two completed clock intervals. There is no request handshake, timeout, or serialized output.

Amendment A2 (Q196, overflow-flag assertion edge). The exact original clauses “When the sum of the next Fibonacci number exceeds 32 bits, the module detects overflow and sets the `overflow_flag` after one clock cycle to propagate the last Fibonacci number to the output, after which it automatically restarts the sequence from F(0) and F(1).”, “If overflow is detected, the `overflow_flag` is set on the next clock cycle to propagate the final Fibonacci number to the output, and the sequence restarts from its initial values, F(0) and F(1).”, “`overflow_flag`: A signal that is set high one cycle after overflow is detected.”, and “If `next_fib` exceeds 32 bits (`next_fib[32]` == 1), `overflow_detected` is set to 1, indicating overflow. On the following clock cycle, this triggers a reset and sets the `overflow_flag`.” are superseded only for overflow_flag assertion timing. The certain answer law states exactly: “On the rising clk edge for which the sum of the two current 32-bit Fibonacci terms has bit 32 set, overflow_flag becomes 1 immediately after that same physical edge.” Restart still occurs at R, the following rising edge; every other part of the quoted clauses remains unchanged.

Amendment A3 (Q192, overflow flag at restart). The exact original clause “It remains high until reset or until the sequence automatically restarts after overflow.” is superseded only for the flag value at and immediately after R. The certain answer law states exactly: “Immediately after D the flag is 1; immediately after R it remains 1 while restart occurs; immediately after the next rising edge it becomes 0.” The same limited amendment applies to the exact original clause “On the next clock cycle, `overflow_flag` is set to 1, `fib_out` resets to 0, and the sequence restarts with `RegA` = 0 and `RegB` = 1.” At R, the data and sequence reset as stated, but overflow_flag retains the 1 asserted at D and clears on the following ordinary edge.

5. Behaviour.

The complete public input domain is all values of the two 1-bit inputs. clk acts only on a rising transition. rst low permits progression; rst high enforces reset with priority over sequence, overflow, and restart activity. Repeated assertions and rising edges while reset is held are idempotent. Release alone changes nothing.

RegA and RegB are unsigned 32-bit terms, reset to F(0)=0 and F(1)=1. At each rising edge with rst low and no pending overflow, `next_fib` is the unsigned 33-bit sum of zero-extended pre-edge RegA and RegB. It is not truncated before bit 32 is tested. When bit 32 is zero, post-edge fib_out and RegA equal pre-edge RegB, while post-edge RegB equals the low 32 bits of `next_fib`. Thus the published sequence after reset is 1, 1, 2, 3, 5, and so on.

When bit 32 is one, D publishes and retains pre-edge RegB=32'hb11924e1 and asserts overflow_flag. R then publishes zero and restores F(0),F(1), while the flag remains high. The following rising edge publishes 1 and clears the flag; later edges repeat the full law. An rst assertion immediately interrupts any phase. There are no disabled inputs or transaction controls: every rising edge with rst low performs the applicable ordinary, detection, restart, or post-restart action.

Amendment A4 (Q199, Clock Cycle 2 publication). The exact original clause “After the clock edge, `RegA` = 1, `RegB` = 2, `fib_out` = 2, `overflow_flag` = 0” is superseded only for fib_out in the source's Clock Cycle 2 illustration. The certain answer law states exactly: “Let E1, E2, E3 be successive rising clk edges after release with no intervening reset: immediately after them fib_out is respectively 32'h00000001, 32'h00000001, and 32'h00000002”. The corrected Clock Cycle 2 value is fib_out=1; RegA=1, RegB=2, and overflow_flag=0 remain unchanged.

Finite-model observation convention: the Lean interface has no physical clk input and uses full-cycle steps. Each step denotes one active rising edge, and each row is observed after settling but before that step. The scenario represents rst held at sampled active edges but not assertions between sampled edges. A row newly presenting rst is the pre-assertion observation; its step combines assertion with coincident-edge reset priority, and the following row observes reset state. This projection does not restrict legal reset pulses or the asynchronous RTL obligation. iface.json specifies neither timing.step_ns nor timing.sample_offset_ns, so no nanosecond spacing or implicit 10 ns clock is asserted.
