Develop the RTL design of First In Last Out (FILO) with the module name `FILO_RTL`. The design `FILO_RTL` has to support various data widths and buffer depths. The FILO should ensure correct data management for push and pop operations while handling edge cases such as feedthrough scenarios. The design must guarantee correct buffer behavior when pushing data into the FILO and popping the data out of it. The FILO buffer stores input data in a stack-like structure, where the most recently pushed data is the first to be popped. 

# FILO Design Specification

The `FILO` (First-In-Last-Out) buffer module stores the input data of configurable widths and manages them in a stack-like manner. The design ensures that data can be pushed into the buffer and popped from it while maintaining control signals for empty and full status.

## Parameters:
- **`DATA_WIDTH`**: Width of the input data to be pushed into the FILO buffer. Default value is 8 bits.
- **`FILO_DEPTH`**: Maximum number of elements the FILO buffer can hold. Default value is 16.

## Interface:

### Inputs:
- **`clk (1-bit)`**: Data operations (push/pop) will be performed on the rising edge of this clock. The clock operates at a 50:50 duty cycle.
- **`reset (1-bit)`**: Asynchronous active-HIGH reset signal to initialize the FILO system. The output `full` will be LOW and `empty` will be HIGH when the `reset` input is HIGH
- **`push (1-bit)`**: Control signal to push data into the FILO buffer. Data is only pushed when the buffer is not full.
- **`pop (1-bit)`**: Control signal to pop data from the FILO buffer. Data is only popped when the buffer is not empty.
- **`data_in` (`DATA_WIDTH` bits, [DATA_WIDTH - 1:0])**: The input data word to be stored in the FILO. The width of this input can vary based on the `DATA_WIDTH` parameter.

### Outputs:
- **`data_out`** (`DATA_WIDTH` bits, [DATA_WIDTH - 1:0]): The data popped from the top of the FILO. The width of this output matches the input data width.
- **`full (1-bit)`**: Status signal indicating whether the FILO buffer is full. Asserted HIGH when the FILO contains the maximum number of elements (`FILO_DEPTH`).
- **`empty (1-bit)`**: Status signal indicating whether the FILO buffer is empty. Asserted HIGH when no elements are present in the FILO.

## Behavior and Operation:
The FILO buffer functions as a stack where the last element pushed into the buffer is the first one to be popped. The FILO buffer's state (full/empty) is updated based on the `push` and `pop` operations.

### Reset Behavior:
- When the **`reset`** signal is asserted, the buffer is cleared:
  - The internal stack pointer (`top`) is reset to 0.
  - The **`empty`** signal is asserted (`empty = 1`), indicating the buffer is empty.
  - The **`full`** signal is deasserted (`full = 0`).

### Push Operation:
- When the **`push`** signal is asserted and the buffer is **not full**, the following occur:
  - The data from `data_in` is stored at the current position indicated by the `top` pointer.
  - The `top` pointer is incremented to point to the next empty position.
  - If the `top` pointer reaches the `FILO_DEPTH`, the **full** signal is asserted (`full = 1`), indicating the buffer is full.
  - The **`empty`** signal is deasserted (`empty = 0`), indicating the buffer contains data.

### Pop Operation:
- When the **`pop`** signal is asserted and the buffer is **not empty**, the following occur:
  - The `top` pointer is decremented to point to the previous data in the buffer.
  - The data at the new `top` position is assigned to `data_out` and output.
  - If the `top` pointer reaches 0, the **empty** signal is asserted (`empty = 1`), indicating the buffer is empty.
  - The **`full`** signal is deasserted (`full = 0`), indicating space is available in the buffer.

## Edge Cases:
**`Feedthrough`**: If the **`FILO`** is empty, and both **`push`** and **`pop`** signals are asserted HIGH in the same positive edge of the `clk`, the input data (`data_in`) is immediately passed through to the output (`data_out`) without being stored in the memory, ensuring minimal latency for this case.

1. Module and ports.

The module name is FILO_RTL.

The public parameters are integer DATA_WIDTH with default 8 and integer FILO_DEPTH with default 16. data_in and data_out are each DATA_WIDTH bits wide, with range [DATA_WIDTH-1:0]. FILO_DEPTH is the maximum number of stored elements. The source requires configurable data widths and depths but does not establish a complete legal parameter domain.

The public named boundary is: input clk, 1 bit; input reset, 1 bit; input push, 1 bit; input pop, 1 bit; input data_in, DATA_WIDTH bits [DATA_WIDTH-1:0]; output data_out, DATA_WIDTH bits [DATA_WIDTH-1:0]; output full, 1 bit; and output empty, 1 bit. These spellings, directions, widths, parameter names, defaults, and symbolic ranges are normative. Q34 confirms named connections to clk, reset, push, pop, data_in, data_out, DATA_WIDTH, and FILO_DEPTH. Named wiring is therefore portable consumer guidance. Neither the source nor Q34 verifies positional declaration order, so the displayed enumeration is not a positional-order guarantee. A caller possessing the actual module declaration may instantiate it positionally in that declaration's order.

3. Reset.

reset is active HIGH and asynchronous. Assertion immediately clears the retained occupancy and sets top to zero independently of clk. While reset is HIGH, empty is HIGH and full is LOW. Reset has priority over push and pop. Reset release alone does not accept an operation or publish data. The cleared empty state persists after release until a rising-edge operation changes it. At the first rising edge after release, the ordinary laws in section 5 apply to the pre-edge controls and cleared state.

Implementation choice C1: before reset has ever been asserted, the concrete finite DATA_WIDTH=8, FILO_DEPTH=16 verification instance starts with zero retained elements, data_out equal to 8'h00, full LOW, and empty HIGH. This is a compatible finite-instance setup, not a source-derived hardware power-up guarantee, and it imposes no reset-before-use restriction on the RTL.

Implementation choice C2: outside the exact DATA_WIDTH=8, FILO_DEPTH=8 source-example coordinates, data_out is zero while reset is asserted and before any successful pop or feedthrough publication. It thereafter retains the most recently published value until another successful pop or feedthrough. This completes only otherwise unconstrained reset and non-result phases; it changes no required result, status, stored value, or transaction. The source example's literal 8'hXX cells remain limited to that example and do not imply initialized memory or hardware X in normal result phases.

Reset clears occupancy; it does not require unused storage words to be initialized. Every occupied word in the finite model originates in an accepted push after the chosen initial setup or after reset.

4. Timing.

Push and pop transactions are accepted on rising edges of clk. The clock duty cycle is 50:50: each HIGH interval and each LOW interval occupies one half of the externally selected clock period. The source supplies no numerical clock period.

full and empty indicate settled occupancy, with an immediate asynchronous reset override. After an accepted edge settles, full is HIGH exactly when occupancy equals FILO_DEPTH, and empty is HIGH exactly when occupancy is zero.

For an ordinary nonempty pop, E0 is the accepting rising edge. The post-E0 data_out is the top item from immediately before E0; removal and occupancy advancement occur on E0. Zero completed subsequent clock intervals elapse before the settled result. The pre-edge top determines the published result even though top and occupancy advance on the same edge.

For empty simultaneous push/pop, E0 is the rising edge at which push and pop are HIGH and pre-edge occupancy is zero. The source-required post-E0 data_out is the low DATA_WIDTH bits of pre-edge data_in, and occupancy remains zero. Zero completed subsequent clock intervals elapse. The word is not stored.

The source example table records the results of its numbered clock cycles. The evaluated SpecIR trace has a separate finite-projection convention: row k observes out(s[k], i[k]) and then step computes s[k+1]. Its interface omits the physical clk, and each step denotes one active-edge scenario. For preservation of the original executable model, empty feedthrough is visible in the row containing both asserted controls; step also retains that published value for later non-result rows. This finite ordering does not amend the RTL requirement that the transaction is accepted at the positive edge. A reset-high row represents reset asserted and held through the observation and represented edge; the projection does not cover every between-edge event and does not restrict legal asynchronous reset pulses. The interface provides neither step_ns nor sample_offset_ns, so row k carries no implicit 10 ns or other wall-clock interval.

5. Behaviour.

Let N be occupancy immediately before an accepting edge, where 0 <= N <= FILO_DEPTH. The top item is the most recently accepted item still retained.

When push is HIGH, pop is LOW, and N < FILO_DEPTH, E0 stores the low DATA_WIDTH bits of pre-edge data_in as the new top and sets occupancy to N+1. When N = FILO_DEPTH, the push is rejected and contents and occupancy remain unchanged.

When pop is HIGH, push is LOW, and N > 0, E0 publishes the pre-edge top on data_out, removes it, and sets occupancy to N-1. When N = 0, the pop is rejected and contents and occupancy remain unchanged.

When push and pop are both LOW, contents and occupancy remain unchanged, and data_out follows Implementation choice C2.

When push and pop are both HIGH and N = 0, E0 performs feedthrough: the low DATA_WIDTH bits of pre-edge data_in are published on data_out without being stored. Post-edge occupancy remains zero, full is LOW, and empty is HIGH.

Implementation choice C3: when push and pop are both HIGH and 0 < N < FILO_DEPTH, both independently enabled operations occur at E0. data_out publishes the pre-edge top; that item is removed; the low DATA_WIDTH bits of pre-edge data_in become the new top; and occupancy remains N. When N = FILO_DEPTH, the pre-edge-full condition rejects push while the enabled pop publishes and removes the pre-edge top, so occupancy becomes FILO_DEPTH-1. This compatible completion resolves only source-unstated simultaneous nonempty behavior. It preserves push-full rejection, pop-nonempty acceptance, LIFO order, every legal input, and the distinct empty-feedthrough requirement.

Accepted stored words are returned by accepted pops in reverse acceptance order. full and empty obey the occupancy predicates above. reset immediately cancels all retained entries. Storage truncates data_in only at the DATA_WIDTH boundary.

There is no behavioral amendment. Q1–Q33 and Q35–Q36 have unclear confidence and supersede no source clause. Q34 establishes only the named integration facts stated in section 1.

Event-sensitivity audit: asynchronous reset assertion clears state and overrides status immediately; reset release makes no state advance; a rising edge accepts each enabled push, pop, or simultaneous transaction; and no mere asserted level advances state without its stated event. From reset assertion through release and the first three rising edges, the post-assertion state is empty, release preserves it, and each edge applies the corresponding pre-edge controls exactly once. Public result publication and occupancy advancement are simultaneous consequences of E0, with data_out computed from pre-edge data or pre-edge top as stated above.
