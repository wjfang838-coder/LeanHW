1. Module and ports.

The module name is exactly gcd_top. It has the public parameter WIDTH, with default value 4 and the constraint WIDTH > 0. A, B, and OUT are each WIDTH bits wide; every other top-level port is one bit wide.

The exact named bindings are: input clk; input rst; input A[WIDTH-1:0]; input B[WIDTH-1:0]; input go; output OUT[WIDTH-1:0]; output done. Q16 confirms connection by name but does not verify positional declaration order. Therefore no positional declaration order is normative, and gcd_top must be instantiated by name. These names are exact.

3. Reset.

rst is active high and synchronous to the positive edge of clk. At every positive edge for which rst is high, the FSM enters S0 (IDLE), the captured operands and OUT become 0, and done becomes 0. Reset has priority over launch and computation on that edge. Because reset is synchronous, changing rst without a positive edge has no effect.

On the first positive edge after rst is released, if go is low, the module remains idle, OUT remains 0, and done remains 0. If go is high with supported operands, that edge launches the transaction; OUT retains 0 and done remains low until completion.

Implementation choice C1: only for physical power-up before any reset edge, the implementation initializes the FSM state, A_ff, B_ff, OUT, and done to their reset values, so OUT reads 0 and done reads 0. This is a compatible implementation decision, not a fact established by the original source or an answer. It creates no reset-before-use restriction and does not change the synchronous-reset contract or any subsequent functional law.

4. Timing.

All FSM state changes, operand updates, OUT updates, and done updates occur on positive edges of clk. rst is sampled on those edges. The source specifies no physical clock period or propagation delay.

OUT is registered. OUT is updated to the computed GCD on the positive edge that completes the calculation and otherwise retains the previously computed GCD, except that a reset edge sets it to 0. done is asserted together with the valid OUT result for exactly one clock cycle and is low in the following cycle as the FSM returns to S0.

A and B are captured on the positive edge across which the one-cycle go pulse is high. The best-case latency, for A equal to B at launch, is 2 clock cycles. The worst-case latency, for A = 1 and B = 2^WIDTH-1, is 2^WIDTH+1 clock cycles. Other supported inputs have data-dependent latency from the required subtraction iterations. The result is output as soon as calculation completes.

For the concrete full-cycle model, row k denotes the observation after k interface steps from settling and is sampled before that row's active edge; it is not an implicit 10 ns clock tick. This table observation convention is separate from the circuit's clock-cycle latency laws. The interface supplies no numeric step_ns or sample_offset_ns.

5. Behaviour.

The Greatest Common Divisor, also called the Greatest Common Factor or Highest Common Factor, is the largest positive integer that divides the operands without remainder. The complete design computes the GCD of unsigned A and B using the subtraction form of the Euclidean algorithm.

The SystemVerilog design consists of gcd_top, gcd_controlpath, and gcd_datapath. gcd_top must instantiate and connect gcd_controlpath and gcd_datapath. OUT is supplied by gcd_datapath and done by gcd_controlpath.

Each module has the public parameter WIDTH with default 4 and WIDTH > 0. gcd_controlpath inputs are one-bit clk, rst, go, equal, and greater_than; its outputs are controlpath_state[1:0] and one-bit done. gcd_datapath inputs are one-bit clk, one-bit rst, unsigned nonzero A[WIDTH-1:0], unsigned nonzero B[WIDTH-1:0], and controlpath_state[1:0]; its outputs are OUT[WIDTH-1:0], one-bit equal, and one-bit greater_than. gcd_top has the interface in section 1.

gcd_controlpath is an FSM with these required states and actions. S0 (IDLE) waits for go and performs no operation until go is received. S1 (DONE) asserts done when equal is active and returns to S0 after the output is provided. S2 (A > B) commands subtraction of B from A. S3 (B > A) commands subtraction of A from B. An unsupported state encoding transitions to S0 without performing a computation. controlpath_state communicates the current registered state to gcd_datapath. Both controlpath_state and done are synchronized to the positive edge of clk.

gcd_datapath stores accepted operands in A_ff and B_ff. In S0, equal and greater_than are combinational comparisons of input A and B. In every other state, they are combinational comparisons of A_ff and B_ff. equal is high exactly when the selected unsigned values are equal; greater_than is high exactly when the selected A value is greater than the selected B value. Both comparison outputs feed gcd_controlpath.

A supported transaction starts when go is high across one positive edge while the FSM is in S0. A and B must be stable and valid before and across that accepting edge and are captured on it. A and B need only be stable and valid before and across the accepting edge; after capture, changes at the top-level A and B pins do not alter the active transaction. The supported operand domain is the unsigned range 1 through 2^WIDTH-1 inclusive. go is high for exactly one clock cycle and remains low until completion. A new transaction may be launched only from the cycle following assertion of done for the preceding transaction.

For every supported transaction, repeated unsigned subtraction is the computation law. If A_ff equals B_ff, their common value is the GCD. If A_ff is greater than B_ff, the next A_ff is A_ff-B_ff and B_ff is unchanged. Otherwise, the next B_ff is B_ff-A_ff and A_ff is unchanged. One directed update occurs per positive edge under the corresponding controlpath_state, and repetition continues until equality. At completion, gcd_datapath assigns the common value to OUT on the positive edge and gcd_controlpath asserts done with that valid result.

OUT is valid and newly updated only together with asserted done. In all other non-reset cycles it retains the previously computed GCD. done is low except for its one-cycle completion pulse.

Zero operands are outside the supported domain. A go assertion during an unfinished transaction, a go pulse longer than one cycle, and launching before the cycle after done are outside the required protocol; their effects are not specified by the RTL contract. These exclusions do not authorize X on OUT or done during a conforming transaction and do not weaken reset behavior. Changes to A or B after their accepting edge are not protocol violations and do not affect the captured transaction.

For WIDTH=16, launching A=4 and B=2 produces OUT=2 together with done=1 for one clock cycle.

Q9 through Q15 are unclear and therefore make no amendments. Their harness observations do not supersede any source clause. There are no scoped amendments to disclose.
