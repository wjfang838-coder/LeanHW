Design a SystemVerilog RTL module `hebbian_rule` that implements a Moore Finite State Machine (FSM) to train a Hebbian learning model. The module takes signed 4-bit inputs (`a` and `b`), a 2-bit gate selector, and control signals for starting the FSM and resetting the system. It sequentially performs training steps such as weight initialization, target selection, weight/bias updates, and convergence checks using the Hebbian learning rule. The module outputs the updated weights (`w1` and `w2`), bias, and the FSM's current state and next state. The system uses a gate selection module to determine the target outputs based on logical gate operations for training.

## Design Specifications:
- Hebbian rule is a type of unsupervised neural network learning algorithm

## Abstract Algorithm:
- The hebbian or hebb rule works based on the following algorithm

-  **Step 1**: Initialize all the weights and bias to zero.
                                  w<sub>I</sub> = 0 for i = 1 to n , n is the number of input vectors

- **Step 2**: For each input training vector and target output pair, do the following:

    - **Step 2a**: Set activation for input units
                         x<sub>i</sub>=s<sub>i</sub>, x is a register to store the input vector, where x is a register to store the input vector

    -  **Step 2b**: Set activation for output unit
                            y = t, where t is the target vector and y is the output vector

    -  **Step 2c**: Adjust the weights and bias
                         w<sub>i</sub>(new) = w<sub>i</sub>(old) + delta_w
                         bias(new) = bias(old) + delta_b
                          Where:
                            delta_w = x<sub>I</sub> * t
                            delta_b = t
                   
## Inputs and Outputs:
## Inputs:
- `clk` (1-bit): Posedge Clock signal.
- `rst` (1-bit): Asynchronous Negedge Reset signal. When asserted LOW , the FSM is initialized to State_0 and iteration counter is initialized to 0.
- `start `(1-bit): Active HIGH Signal to initiate the FSM.
- `a`, `b` (4-bit each, [3:0],signed): Bipolar input signals [-1 ,1]. Only -1 and 1 have to be considered as valid inputs
- `gate_select` (2-bit,[1:0]): Selector to specify the target for a given gate
## Outputs:
- `w1`, `w2` (4-bit each,[3:0], signed): Trained weights for the inputs.
- `bias` (4-bit, signed,[3:0]): Trained bias value.
- `present_state`, `next_state` (4-bit each,[3:0]): Current and next states of the Training FSM.

## Learning Logic:
- Weights (w1, w2) and bias are updated incrementally based on the input values and a computed error:
    delta_w1 = x1 * target
    delta_w2 = x2 * target
    delta_b = target 
    w1 = w1 + delta_w1
    w2 = w2 + delta_w2
    bias = bias + delta_b

- Target values are determined using a `gate_target` submodule based on `gate_select`:
  - gate_select = 2'b00: AND gate behavior.
  - gate_select = 2'b01: OR gate behavior.
  - gate_select = 2'b10: NAND gate behavior.
  - gate_select = 2'b11: NOR gate behavior.

## FSM Design:
There are totally 11 states handled by Moore FSM.
- State_0: Reset state.
- State_1: Capture inputs.
- State_2-State_6: Assign targets based on the selected gate.
- State_7: Compute deltas for weights and bias.
- State_8: Update weights and bias.
- State_9: Loop through training iterations.
- State_10: Return to the initial state.

## Functional Requirements:
- Weight adjustment must follow the Hebbian learning rule.
- The FSM must support multiple training iterations for every possible input combination of a two-input logic gate.
- Outputs (`w1`, `w2`, `bias`) should reflect trained values at the end of the process.

## Testbench:
- Validate learning for all gates (`gate_select` = 2'b00 to 2'b11).
- Test with various input combinations (`a`, `b`) to observe weight and bias updates.
- Ensure the FSM transitions and outputs align with the design.

## Example Calculation:
Let us take the AND gate for explaining the working of the module.
Let the 4-bit inputs be : `a = 4'b0001` and `b = 4'b0001`.
The target expected for this input combination is `4'b0001`.

## Algorithmic Explanation :
-  1. Initialize the weights and bias registers to 0
            `w1 = 4'b0000` , `w2 = 4'b0000` , `bias = 4'b0000`;
-  2. Capture the inputs `a` and `b` into two internal registers namely x1 and x2.
            `x1 = 4'b0001` (Holds the contents of operand `a`)
            `x2 = 4'b0001` (Holds the contents of operand `b`)
-  3. Select the target required for the given input combination 
          ` t1 = 4'b0001`
-  4. Calculate the incremental values of w1(`delta_w1`), w2(`delta_w2`), b(`delta_b`)
            `delta_w1 = x1 * t = 4'b0001 * 4'b0001 = 4'b0001`
            `delta_w2 = x2 * t = 4'b0001 * 4'b0001 = 4'b0001`
            `delta_b  = t = 4'b0001`
-  5. Calculate the values of w1 , w2 , bias
            `w1   = w1 + delta_w1  = 4'b0000 + 4'b0001 = 4'b0001`; (1 in decimal)
            `w2   = w2 + delta_w2  = 4'b0000 + 4'b0001 = 4'b0001`; (1 in decimal)
            `bias = bias + delta_b = 4'b0000 + 4'b1111 = 4'b0001`; (1 in decimal)

1. Module and ports.



3. Reset.

rst is an asynchronous active-LOW reset with priority over coincident clock and control activity. Physical assertion E0 immediately makes each of w1, w2, bias, and present_state 4'b0000 without waiting for clk and clears the prior item-qualification history. These four outputs remain zero while rst is LOW. During reset, next_state remains combinational: it is 4'b0000 when start is LOW and 4'b0001 when start is HIGH.

Reset release changes no registered output and accepts no item. At the first subsequent rising edge E1, normal state capture and input-item processing resume from State_0. Immediately before E1, the registered outputs still have their reset values.

Before rst has ever been asserted and before their respective assignments, w1, w2, bias, and present_state have no initialized value and are unknown. A rising edge with start LOW establishes present_state as State_0. A qualifying rising edge establishes w1, w2, and bias. next_state is still known as 4'b0000 whenever start is LOW. This power-up statement is not a reset-before-use input restriction.

4. Timing.

Only a rising edge of clk advances registered state; falling edges have no effect. w1, w2, bias, and present_state are registered outputs. next_state is continuously combinational from start and present_state.

For a qualifying tuple, E0 is its accepting rising edge. The pre-E0 values of a, b, gate_select, w1, w2, bias, and qualification history determine the registered post-E0 data outputs. The same edge separately advances present_state and qualification history. The pre-E0 observation contains the old registered values; immediately after E0 the updated registered values are visible, and the next pre-edge observation contains them. There is no separate completion pulse or later publication edge. A nonqualifying rising edge retains w1, w2, and bias.

The finite Lean model has no physical clk input. Each full-cycle step denotes one rising edge. Row k drives its inputs, settles combinational logic, and samples outputs before that edge; the edge produces the state sampled in row k+1. Reset rows represent rst held LOW through the represented edge. The projection does not represent every between-edge instant and does not weaken the asynchronous-reset contract. iface.json supplies neither step_ns nor sample_offset_ns, so the rows do not imply a 10 ns tick.

5. Behaviour.

The natural four-bit state encodings are State_0=4'd0, State_1=4'd1, State_2=4'd2, State_3=4'd3, State_4=4'd4, State_5=4'd5, State_6=4'd6, State_7=4'd7, State_8=4'd8, State_9=4'd9, and State_10=4'd10.

start LOW makes next_state 4'd0. start HIGH makes next_state 4'd1 when present_state is 4'd10 and otherwise makes next_state equal to present_state plus one modulo 16. At every rising edge with rst HIGH, present_state captures the next_state value from immediately before that edge. Consequently uninterrupted start HIGH progresses 0,1,...,10,1,...; start LOW returns present_state to 0 at that edge. Data-output qualification does not delay state progression.

The environment supplies training tuples. A tuple (a,b,gate_select) qualifies at a rising edge exactly when rst is HIGH, start is HIGH, and it is the first such tuple after reset or after a start-LOW rising edge, or at least one tuple field differs from the most recently qualified tuple. Exact repeats with uninterrupted start HIGH do not qualify and retain w1, w2, and bias. A start-LOW edge retains these three outputs but ends continuity, so the next start-HIGH tuple qualifies even when identical. Qualified tuples need not be on consecutive edges.

For a qualifying tuple, gate_select selects signed four-bit target t. For 2'b00 (AND), t is 4'b0001 only when a and b both equal 4'b0001, and otherwise is 4'b1111. For 2'b01 (OR), t is 4'b1111 only when neither operand equals 4'b0001, and otherwise is 4'b0001. For 2'b10 (NAND), t is 4'b1111 only when both operands equal 4'b0001, and otherwise is 4'b0001. For 2'b11 (NOR), t is 4'b0001 only when both operands equal 4'b1111, and otherwise is 4'b1111. The source requires target determination by gate_target but supplies no submodule definition to reproduce.

All four-bit a and b encodings are accepted when the tuple otherwise qualifies. The truth tests above treat only 4'b0001 as true, and NOR's true case requires two exact 4'b1111 operands.

a, b, and t are signed four-bit two's-complement operands. delta_w1 is the low four bits of the signed product a*t, delta_w2 is the low four bits of the signed product b*t, and delta_b is t. Normally, post-E0 w1 is pre-E0 w1 plus delta_w1 modulo 16, post-E0 w2 is pre-E0 w2 plus delta_w2 modulo 16, and post-E0 bias is pre-E0 bias plus t modulo 16. Each signed product is evaluated in its product expression context and explicitly truncated to its low four bits at the delta boundary; each addition is then explicitly truncated to four bits. Arithmetic wraps and does not saturate or clamp.

If start has stayed HIGH since the preceding qualified tuple and gate_select changes, the accepting edge instead replaces the outputs: post-edge w1=delta_w1, post-edge w2=delta_w2, and post-edge bias=t. If reset or a start-LOW edge intervened, ordinary accumulation applies to the next tuple, starting from zero after reset or from the retained values after start LOW.

When present_state is State_9, there is no iteration-count or convergence test. start HIGH makes next_state State_10; start LOW makes it State_0. The next rising edge captures that value. Reaching State_9 neither clears nor separately commits the data outputs, although a tuple independently qualifying on that edge performs its normal update.
