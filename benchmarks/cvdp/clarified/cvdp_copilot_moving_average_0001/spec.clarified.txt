Design a Verilog module that computes the **moving average** of an incoming **12-bit data stream**. The module should output the integer average of the last 8 input unsigned value samples. 1. Module and ports.

The module name is moving_average.

The confirmed named boundary consists of input clk, 1 bit; input reset, 1 bit; input data_in, 12 bits; and output data_out, 12 bits. These spellings are exact. Connections must be made by name. Positional declaration order is unverified and therefore is not normative. No public parameters, default parameter values, or symbolic port-width expressions are established by the authorized source.

3. Reset.

Reset is synchronous and active high. It has an effect only when sampled on a rising edge of clk. On such an edge, reset has priority over data_in, clears data_out to zero, and clears the entire memory buffer so that no earlier sample contributes. Each repeated rising edge with reset high preserves that cleared condition. Assertion or release between rising edges has no independently specified effect.

On the first rising edge after reset is released, the current unsigned data_in is accepted as the first sample of a fresh calculation. The value established after that edge is integer-truncated data_in divided by eight.

Before the first rising edge that samples reset high, the hardware power-up value of data_out and the memory-buffer contents are not specified by the original requirements. This omission is not permission to drive X, is not a zero guarantee, and does not forbid a reset-low rising edge from performing the normal update. The documented synchronous reset sequence establishes the specified known fresh state when it occurs; the source does not impose or describe a reset-before-use input restriction.

For the finite worked-trace/model scope only, every stimulus block starts from the state reached after a rising edge sampled reset high: data_out is zero and the complete prior-sample contribution is cleared. This verification setup makes the first displayed row deterministic. It is separate from the RTL contract and adds neither a hardware power-up guarantee nor a value for uninitialized physical storage.

4. Timing.

All specified transactions occur on rising edges of clk. data_out is registered. A reset-low rising edge accepts data_in and establishes the corresponding result immediately after that edge; with the pre-edge table convention, that result appears in the following row. Between rising edges, data_out retains the last established value. A reset sampled in row k makes zero visible in row k+1 and repeated reset edges keep it zero. There is no completion pulse, periodic output, or terminal state.

The evaluated object uses full-cycle observations: row k is the settled output before active edge k, and that edge computes the state observed in row k+1. iface.json provides neither timing.step_ns nor timing.sample_offset_ns, so no nanosecond spacing is implied. Separately, the circuit law identifies rising edges but specifies neither a physical clock period nor a propagation delay.

5. Behaviour.

Each rising edge of clk performs one transaction. When reset is asserted it clears the observable moving-average history and result with priority over data_in; otherwise it samples data_in and produces the sum of the newest sample and up to seven preceding samples divided by eight using integer truncation. Repeated rising edges repeat this operation; steady clock levels and falling edges have no specified effect, and no additional mode or interruption behavior is established.

Reset is active high and, when sampled asserted on a rising clk edge, takes priority over data_in and clears data_out and all prior-sample contribution so repeated asserted edges keep data_out at zero; when reset is low normal sampling resumes fresh, while assertion or release away from a rising edge has no independently established effect.

On every rising clk edge with reset low, the 12-bit data_in value is accepted as the newest sample and the resulting value is the integer-truncated sum of that sample and up to the seven previously accepted samples divided by eight, with samples older than eight discarded; data_in is ignored when reset is sampled high and changes between sampling edges have no specified effect.

The divisor is always eight. If fewer than eight samples have been accepted since the last effective reset, unavailable positions contribute zero: data_out is the unsigned sum of all available post-reset samples divided by eight with integer truncation.

The sum preserves the complete unsigned range of eight 12-bit operands through every addition. Division by eight occurs in that full-width unsigned expression context. Only the quotient is confined to the 12-bit data_out boundary; no addition, division-equivalent shift, or other intermediate expression is first truncated to 12 bits.

Because each tabular row is sampled before its active edge, data_out in row k retains the result of the preceding rising edge, a reset asserted in row k makes zero observable in row k+1 and keeps it zero across repeated reset edges, and after release each reset-low rising edge captures a sample whose new fixed-eight-sample, integer-truncated average becomes observable in the following row and is retained until the next rising-edge result or reset clear; operation has no completion state and restarts fresh after reset.

Valid unsigned input is continuously available and accepted on every reset-low rising edge. There is no start, valid, ready, enable, cancellation, disable, completion, restart handshake, or terminal mode. The single reset rule covers simultaneous reset and data input by ignoring data_in. Public-output updates and history advancement follow the separate edge conditions above.
