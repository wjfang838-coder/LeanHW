Design a SystemVerilog RTL module `perceptron_gates` that implements a microcoded controller to train a perceptron model. The module takes signed 4-bit inputs (x1 and x2), a 4-bit threshold, a 1-bit learning rate, and a 2-bit gate selector to determine the target output based on logical gate operations. It uses a microcode ROM to sequentially execute actions like weight initialization, output computation, target selection, weight/bias updates, and convergence checks. The module outputs the updated weights, bias, perceptron response (y), and a stop signal when training converges.

## Design Specification:
The `perceptron_gates` module handles weight initialization, computation of perceptron outputs, target selection based on input indexes, and weight and bias updates. It features a microcoded approach for defining operational states, ensuring flexibility and reusability for perceptron-based learning tasks.

## Interface
## Inputs
- `clk` (1-bit): Positive edge-triggered clock signal for calculating the microcode ROM address.
- `rst_n` (1-bit): Negative edge-triggered reset signal. When ACTIVE LOW, `present_addr` is initialized to `4'd0`.
- `x1`, `x2` (4-bit,[3:0], signed): Perceptron inputs. Can take only Bipolar values [`4'd1`,`-4'd1`]
- `learning_rate` (1-bit): Learning rate for weight and bias updates.
- `threshold` (4-bit,[3:0], signed): Threshold value for response calculation.
- `gate_select` (2-bit,[1:0]): Specifies the gate type for determining target outputs.

## Outputs
- `percep_w1`, `percep_w2` (4-bit, [3:0], signed): Current weights of the perception. Can take any signed 4-bit value, including zero; additions wrap modulo 16 at the public 4-bit boundary.
- `percep_bias` (4-bit,[3:0], signed): Current bias of the perception.Can take any signed 4-bit value, including zero; additions wrap modulo 16 at the public 4-bit boundary.
- `present_addr` (4-bit,[3:0]): Current microcode ROM address.
- `stop` (1-bit): Indicates the end of training.
- `input_index` (3-bit,[2:0]): Tracks the current target value selected during an iteration. Can take values from 3'd0 to 3'd3.
- `y_in` (4-bit,[3:0] signed): Raw signed weighted sum plus bias, truncated to the signed 4-bit output width; it is not limited to bipolar values.
- `y` (4-bit, [3:0], signed): Perceptron output after applying the threshold.Can take three different values [`4'd1`,`4'd0`,`-4'd1`]
- `prev_percep_wt_1`, `prev_percep_wt_2`, `prev_percep_bias` (4-bit, [3:0], signed): Weights and Bias during a previous iteration. Can take any signed 4-bit value, including zero; additions wrap modulo 16 at the public 4-bit boundary.

## Submodule Overview
### 1. Gate Target (`gate_target`)
Generates target outputs (`t1`, `t2`, `t3`, `t4`) based on the selected gate type.
- Inputs: `gate_select` (2-bit,[1:0]).
- Outputs : `o_1`, `o_2`, `o_3`, `o_4` (4-bit, [3:0],signed).
- Gates implemented: AND, OR, NAND, and NOR gates.
   - `gate_select`:
         - `2'b00` : AND Gate    ; target values : (`4'd1`,`-4'd1`,`-4'd1`,`-4'd1`)
         - `2'b01` : OR Gate      ; target values : (`4'd1`, `4'd1`, `4'd1`,`-4'd1`)
         - `2'b10` : NAND Gate ; target values : (`4'd1`, `4'd1`, `4'd1`,`-4'd1`) 
         - `2'b11` : NOR Gate   ;  target values : (`4'd1`, `-4'd1`, `-4'd1`,`-4'd1`) 
         
### 2. Microcode ROM
- Defines a sequence of 6 micro-instructions, specifying actions such as weight initialization, output computation, target selection, and weight/bias updates.

## Algorithm Steps for Perceptron Learning
- Initialization: All weights, biases, and counters are set to zero.
- Compute Output: Compute `y_in` = `bias` + (`x1` * `w1`) + (`x2` * `w2`) and compare with the threshold to determine `y`.
- Select Target: Based on `gate_select` and` input_index`, pick the desired target value
- Update Weights and Bias: Adjust weights and bias  based on the condition (`y` != `target`)
  -  If the condition is satisfied
        - `wt1_update` = `learning_rate` * `x1` * `target`
        - `wt2_update` = `learning_rate` * `x2` * `target`
        - `bias_update` = `learning_rate` * `target`
   - If the condition is not satisfied
        - `wt1_update` = 0
        - `wt2_update` = 0
        - `bias_update` = 0
  - The value of current weights and bias is calculated as follows :
       - `percep_wt1` = `percep_w1` + `wt1_update`
       - `percep_wt2` = `percep_wt2` + `wt2_update`
       - `percep_bias` = `percep_bias` + `bias_update`
- Check if the `wt1_update`, `wt2_update` , and `bias_update` values are equal to their previous iteration values. If the condition is satisfied, stop the learning. Otherwise assign the `wt1_update`, `wt2_update`, and `bias_update` values to their previous iteration values and continue learning.
                                                 
## Control Flow
### Microcoded Actions
- Action 0: Initialize weights and bias to zero.
- Action 1: Compute `y_in` (weighted sum + bias) and `y` (thresholded output).
- Action 2: Select target value based on `input_index `and `gate type`.
- Action 3: Update weights and bias if the perceptron output differs from the target.
- Action 4: Compare current and previous weights and bias to determine convergence.
- Action 5: Finalize updates and prepare for the next epoch.
**An epoch is the time taken to train the perceptron for a given combination of four input values**

## Key Features
- Microcoded Sequencing: Flexible execution of training steps using `microcode ROM`.
- Dynamic Target Selection: Allows gate-based logic outputs for versatile applications.
- Sequential Updates: Tracks and applies weight changes across iterations.
- Convergence Monitoring: Halts training when weights stabilize.

Local experimental completion of perceptron laws. These exact rules supersede conflicting earlier arithmetic, previous-value descriptions, convergence shorthand and illustrative waveform timing. They are explicit benchmark definitions, not recovered designer intent:
- All public signed values are 4-bit two's complement. Compute the mathematical signed sum bias+x1*w1+x2*w2, then wrap it to four bits for y_in; compare that signed wrapped value, not the untruncated sum, with the signed 4-bit threshold to produce y=1,0,-1. Weight, bias and previous-delta additions wrap to four bits. Learning rate is unsigned 0 or 1.
- Initialization and asynchronous active-low reset zero all public outputs and internal state, with present_addr=0,input_index=0,stop=0. Reset overrides a simultaneous clock edge. Only rising clk edges perform normal actions. Public outputs retain their values between actions and on falling edges. Reset may interrupt any phase and restarts the controller. There is no implicit warm-up requirement.
- The six microcode addresses are 0..5. Address 0 occurs only immediately after initialization/reset: its rising edge retains zero weights and advances to 1. Address 1 samples x1,x2,learning_rate,threshold and gate_select, publishes y_in and y using the current pre-edge weights, then advances to 2. Values captured here are used for the complete sample; input changes during addresses 2..5 do not affect it. Both inputs may be any bipolar combination for any input_index; the worked example's order is an example, not an input restriction.
- Address 2 chooses target from the captured gate_select and current input_index using the four listed tuples, then advances to 3. Address 3 computes deltas: when the captured y differs from target, delta_w1=learning_rate*x1*target, delta_w2=learning_rate*x2*target, delta_bias=learning_rate*target; otherwise all deltas are zero. It immediately publishes weights/bias plus these deltas and records whether any nonzero delta occurred in the current four-sample epoch, then advances to 4.
- Address 4 publishes the just-computed deltas on prev_percep_wt_1,prev_percep_wt_2,prev_percep_bias; these legacy-named outputs represent update deltas, not previous absolute weights. It decides convergence only if input_index=3 and the entire current epoch has had zero deltas, then advances to 5. Equality between adjacent nonzero deltas does not establish convergence.
- Address 5 finalizes the sample. If the preceding convergence decision is true, set stop=1, retain present_addr=5 and input_index=3, and freeze all public outputs and training state until reset, regardless of later input changes. Otherwise increment input_index modulo four and return to address 1, retaining learned weights. After index 3 finalize, clear the epoch-change accumulator for the next epoch. Public y/y_in remain the values published by address 1; previous-delta outputs remain the values published by address 4. A gate change affects only the next address-1 capture and never resets weights or restarts a stopped controller by itself.

2. Reset

The source's final explicit experimental completion governs conflicting earlier descriptions. Initialization and asynchronous active-low reset set every public output and all training state to zero. This includes captured operands and controls, target, pending update amounts, epoch history, convergence decision and stopped state. Before any reset assertion, initialization has already established those zero values; this is an explicit source initialization requirement, not an inference from the finite model. Assertion interrupts every phase and a stopped run, discards the captured sample and epoch history, and takes priority over a simultaneous rising edge. All state and outputs stay zero while rst_n is low, including through clock edges. Release alone retains zero. The first rising edge after release changes only present_addr to 1. The second rising edge captures the first sample and publishes y_in and y; the third selects its target. No reset-before-use or warm-up restriction is added.

3. Timing

Only rising clk edges perform normal actions. Every public output is registered and retains its published value between actions and on falling edges; asynchronous reset is the stated exception. No periodic output or completion pulse is specified: stop is a retained level until reset.
For each sample E0 is the rising edge with pre-edge present_addr=1, rst_n=1 and stop=0. It accepts x1, x2, learning_rate, threshold and gate_select, publishes y_in and y, and advances present_addr to 2. E1, E2, E3 and E4 follow after one, two, three and four completed clock intervals from E0, respectively. Their pre-edge addresses are 2, 3, 4 and 5. E1 selects the captured gate's target and publishes address 3. E2 publishes the updated percep_w1, percep_w2 and percep_bias and address 4. E3 publishes prev_percep_wt_1, prev_percep_wt_2 and prev_percep_bias and address 5. E4 finalizes the sample, publishes stop if converged, and otherwise advances input_index modulo four and returns present_addr to 1. input_index remains the pre-E0 index through E3; convergence at E4 retains index 3 and address 5. Thus y_in/y latency is zero subsequent intervals from acceptance, weight/bias latency is two, previous-delta latency is three, and completion latency is four. The next nonstopped sample is accepted one interval after E4. No release event consumes a sample edge.
Published values after an edge use the state and operands before that edge, separately from simultaneous address or index advancement. In particular E0 uses pre-edge weights, E1 uses the retained sample index, E2 adds the sample's deltas to the pre-edge weights, E3 publishes those retained deltas, and E4 uses the preceding convergence decision. Outputs not named for an action retain their values.

4. Behaviour

Interpret signed four-bit values as two's complement integers in -8..7; learning_rate is unsigned 0 or 1. Define S4(v)=((v+8) mod 16)-8, with nonnegative modulo, and encode signed outputs modulo 16. At E0 let A,B,L,H,G denote the accepted x1,x2,learning_rate,threshold,gate_select, let i denote input_index, and W1,W2,C denote pre-edge percep_w1,percep_w2,percep_bias. Compute the mathematical signed sum C+A*W1+B*W2 before truncation, set R=S4(C+A*W1+B*W2), and compare this signed wrapped R with H: Y=1 above, Y=0 equal, Y=-1 below. Publish y_in=R and y=Y at E0. There is no narrower intermediate expression truncation; the specified boundary is the signed four-bit raw sum and each published four-bit addition/update amount.
T is element i of (1,-1,-1,-1) for G=0 or 3, and of (1,1,1,-1) for G=1 or 2. These are the normative lookup tables despite the legacy NAND/NOR labels. At E1 choose T using captured G and the sample index, independent of the live bipolar combination. Define g=L*T if Y differs from T and g=0 otherwise. The mathematical deltas are (g*A,g*B,g). At E2 publish (S4(W1+g*A),S4(W2+g*B),S4(C+g)) on the three weight/bias ports. At E3 publish (g*A,g*B,g) modulo 16 on the three previous-delta ports. Those ports denote update amounts, not previous absolute weights.
An epoch consists of four samples at indices 0,1,2,3. Remember whether any mathematical delta was nonzero anywhere in that epoch. At E3 convergence is decided only when i=3 and all deltas throughout that epoch were zero. At E4 assert stop for convergence and freeze every output and all training state until reset; otherwise increment the index modulo four, return to address 1 and retain learned weights. When finalizing index 3 without convergence, clear the epoch-change history for the next epoch. Equal adjacent nonzero updates never imply convergence. L=0 gives a zero-update epoch even with classification mismatches, but no isolated zero update completes before index 3.
Every data/control input is accepted only at E0 while running. Changes at address 0 or addresses 2..5 do not alter a pending sample. Later address-1 edges accept the then-current values. x1 and x2 affect the raw sum and their respective update products; their effect on Y also affects all deltas. threshold affects Y and the mismatch but not R. learning_rate affects deltas but neither R nor Y. gate_select affects T and deltas but neither R nor Y; a gate change does not clear weights. Inputs never restart a stopped controller; reset does. No separate request, busy exclusion or cancellation control exists. Reset alone cancels a pending sample. y_in/y retain the last E0 result, weights/bias the last E2 result, and previous-delta outputs the last E3 result until their next publication or reset.
