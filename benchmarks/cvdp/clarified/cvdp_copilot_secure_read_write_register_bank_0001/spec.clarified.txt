<!-- original-requirements:start -->
Design a parameterized register bank module with secure access control in Verilog. The module named `secure_read_write_register_bank` should allow read and write operations only after unlocking, which requires specific values written to the first two addresses in sequence. Once unlocked, the register bank operates as specified below.

## Parameter
1.  **p_address_width**: The address width parameter with default value of 8 bits. It will be used to create the addressable space of register bank module.
2.  **p_data_width**: The data width parameter with default value of 8 bits.
3. **p_unlock_code_0**: The unlock code to be written at address zero. The default value is 0xAB.
4. **p_unlock_code_1**: The unlock code to be written at address one. The default value is 0xCD.


## Inputs
1. **i_addr**: `p_addr_width`-bit input. Specifies the target address for read or write operations.
2. **i_data_in**: `p_data_width`-bit input. Data input to be written to the register bank during a write operation.
3. **i_read_write_enable**: 1-bit input control signal. Determines the operation type:
   - `0`: Write operation.
   - `1`: Read operation.
4. **i_capture_pulse**: 1-bit capture pulse signal. Triggers the read or write operation on positive edge of this signal. It will act as clock for register bank.
5.  **i_rst_n**: 1-bit asynchronous active low reset, to reset the unlock state machine

## Outputs
1. **o_data_out**: `p_data_width`-bit output. Data output bus that reflects the value read from the register bank during a read operation.

## Functional Requirements

### 1. Write Operation
   - If **i_read_write_enable** is `0`, the module interprets this as a write operation.
   - On the **rising edge** of **i_capture_pulse**, the value of **i_data_in** is written to the register at the address specified by **i_addr**.
   - **o_data_out** should output `0` during write operations as a default state.

### 2. Read Operation
   - If **i_read_write_enable** is `1`, the module interprets this as a read operation.
   - On the **rising edge** of **i_capture_pulse**, **o_data_out** outputs the data stored at the address specified by **i_addr**.
   - **o_data_out** only reflects the read data during read operations.

## Security Access Requirements
1. **Unlocking Mechanism**:
   - **To unlock the register bank**, two sequential operations must be completed:
     - First, the specific **parameterized unlock code** (matching **p_data_width**) must be written to address `0`.
     - Then, a specific **parameterized trigger code** must be written to address `1`.
   - If both conditions are met, the register bank unlocks, enabling access to read and write for all addresses.
   - If, at any positive edge of i_capture_pulse, values are written to address 0 or 1 does not equal to given parameterized unlock code, the register bank will reset, resulting in lock of register bank. User needs to unlock the register bank once again.
   - If the unlock sequence is incomplete, access to other addresses will remain restricted as follows:
     - **Read Operation**: Outputs `0` on **o_data_out**.
     - **Write Operation**: Prevents writing to any address except `0` and `1`.
   - When i_rst_n goes low, then this unlocking mechanism resets and user needs to unlock the register bank once again.

2. **Restricted Access Addresses**:
   - Addresses `0` and `1` are write-only and cannot be read.
   - Other addresses remain inaccessible for both read and write until the unlock sequence is completed.

## Constraints and Edge Cases
- Ensure that addresses `0` and `1` cannot be read.
- Any read or write attempt on other addresses before unlocking should default **o_data_out** to `0` and prevent writing, respectively.
- The writing of address `0` and address `1` should be concurrent, else register bank should be locked.

## Verification and Test Cases
1. **Write Operation Test**: Verify that data can be written only after the register bank is unlocked.
2. **Read Operation Test**: Confirm that data is output only on successful read operations.
3. **Unlock Sequence Test**: Test various sequences to confirm that only the correct sequence unlocks the register bank.
6. **Access Restriction Test**: Ensure that all addresses except `0` and `1` remain inaccessible until unlocked.

1. Module and ports.



3. Reset.

i_rst_n is an asynchronous, active-low reset. While i_rst_n is low, access is locked, any partial unlock sequence is cancelled, transaction inputs have no effect, and o_data_out is immediately all zeros. Reset does not alter ordinary register-bank contents.

Release alone performs no transaction. After release, access remains locked and o_data_out remains zero until a later rising edge of i_capture_pulse performs a transaction. The first such edge is processed from the locked state.

Implementation choice C1: At hardware power-up, before reset has ever been asserted, access is locked, the partial unlock state is empty, o_data_out is all zeros, and every ordinary register-bank entry contains all zeros. This exact initial-state scope is a compatible implementation decision because the source does not establish power-up values for those elements. It is not a source-derived hardware fact, does not require reset before use, and does not make reset clear or rewrite stored entries. Consequently, an authorized read of an ordinary address that has never been written returns all zeros; an authorized write replaces that entry, and its value is retained across reset.

4. Timing.

i_capture_pulse is the transaction clock. Exactly one transaction occurs on each rising edge while i_rst_n is high. Low or steady clock levels cause no transaction. i_addr, i_data_in, and i_read_write_enable are sampled at that edge and have no transaction effect between rising edges. Reset assertion acts asynchronously and can interrupt without waiting for an edge.

o_data_out is transaction-registered except for asynchronous reset. A transaction result becomes observable immediately after its accepting rising edge and remains until reset assertion or the next transaction edge. Under the normative pre-edge observation convention, this is one capture-edge latency. Every captured write, rejected operation, locked read, and read of address 0 or 1 sets o_data_out to zero after that edge. There are no pulse or periodic outputs.

For the concrete full-cycle model, row k denotes abstract cycle k after settling: it observes out(s[k], i[k]) before abstract rising edge k, and that edge computes s[k+1]. The interface supplies no timing.step_ns or timing.sample_offset_ns, so row numbers imply neither a 10 ns tick nor any physical clock period or propagation delay.

5. Behaviour.

The bank has 2**p_address_width entries of p_data_width bits each. Addresses 0 and 1 are reserved write-only unlock addresses; reads of either always return all zeros. All other addresses are ordinary storage.

Amendment A1 (Q1, limited scope). Exact superseded original clause: “The writing of address `0` and address `1` should be concurrent, else register bank should be locked.” Exact certain answer law: “After consecutive writes of the two configured unlock codes to addresses 0 and 1, respectively, writes to any other address store i_data_in and a later read of that address captures the stored value for observation after that read edge; reset instead makes the subsequent value zero until another successful unlocked read.” Within Q1's observable-coordinate scope and its general law—successful unlocking, subsequent ordinary-address storage/readback, and reset effect—the quoted answer supersedes only the quoted concurrent-writing clause: the two qualifying code writes occur on consecutive rising edges, first at address 0 and then at address 1. All other original requirements remain unchanged.

Access starts locked. Two qualifying writes on consecutive rising edges while i_rst_n is high unlock it: first p_unlock_code_0 to address 0, then p_unlock_code_1 to address 1. A repeated valid first-code write to address 0 restarts the partial sequence. After a first qualifying write, any other captured operation except another valid first-code write or the required second-code write cancels the partial sequence and leaves access locked.

i_read_write_enable is one bit: 0 selects write and 1 selects read. While locked, reads of all addresses set o_data_out to zero; writes to ordinary addresses are prevented and set o_data_out to zero. Wrong code writes to address 0 or 1 leave or return access to locked.

While unlocked, a write to an ordinary address stores the current p_data_width-bit i_data_in in that entry and sets o_data_out to zero. Repeated edges perform independent writes. A valid first-code write to address 0 relocks access and starts a new partial sequence. Any other write to address 0 or 1 relocks access, except the required second-code write immediately following a partial sequence, which completes unlocking.

While unlocked, a read of an ordinary address ignores i_data_in, does not alter storage, and captures that entry's retained value into o_data_out. A read of address 0 or 1 captures all zeros. Every read or other intervening operation during a partial unlock cancels that partial sequence. Stored ordinary data survives reset; C1 governs an entry until its first authorized write.

At each rising edge while reset is high, i_addr selects the operation and repeated captures apply independently; between edges it has no effect. For writes, i_data_in supplies unlock codes or ordinary stored data; reads ignore it. i_read_write_enable=0 is required for code and data writes, while i_read_write_enable=1 reads and cannot advance an unlock sequence. A low or steady i_capture_pulse pauses transactions; each rising edge advances exactly one, and operation resumes on the first rising edge after reset release. i_rst_n low asynchronously locks, cancels a partial sequence, forces o_data_out to zero, and pauses transactions; later assertions remain effective. o_data_out retains its registered value between edges, is replaced by every later transaction according to these laws, and has no terminal state.

The implementation shall be verified across authorized reads and writes, successful and failed unlock sequences, repeated first-code writes, every intervening-operation cancellation, relocking through addresses 0 and 1, locked restrictions, write-only readback, reset assertion and release, repeated transactions, C1 initial reads, retained data across reset, and every supported parameter value.
