Please act as a professional verilog designer.

Implement an asynchronous FIFO, FIFO bit width and depth can be configured(parameter DEPTH = 16, parameter WIDTH = 8). The asynchronous FIFO structure is divided into several parts. The first part is dual-port RAM, which is used for data storage. Instantiate dual-port RAM as a submodule, The RAM ports are input wclk, input wenc, input [$clog2(DEPTH)-1:0] waddr, input [WIDTH-1:0] wdata, input rclk, input renc, input [$clog2(DEPTH)-1:0] raddr, output reg [WIDTH-1:0] rdata. The second part is the data write controller. The third part is the data read controller. The fourth part is the read pointer synchronizer. The read pointer is collected using the two-stage trigger of the write clock and output to the data write controller. The fifth part is the write pointer synchronizer, which uses the two-stage trigger of the read clock to collect the write pointer and output it to the data read controller.
The method of empty and full judgment is to generate empty and full signals by comparing the Gray code. Use 4-bit Gray code as a read/write pointer for a FIFO with depth 8. The gray code is converted to a four-digit binary number, using the lower three digits of the binary number as the address to access RAM. When the read and write Pointers are equal, the FIFO is null.
When the write pointer has one more cycle RAM than the read pointer, the highest and second-highest bits of the read and write pointer are opposite, the remaining bits are the same, and the FIFO is full.

Module name:  
    asyn_fifo  

Input ports:
	wclk: Write clock signal used for synchronous write operations.
	rclk: Read clock signal used for synchronous read operations.
	wrstn: Write reset signal. Defined as 0 for reset and 1 for reset signal inactive.
	rrstn: Read reset signal. Defined as 0 for reset and 1 for reset signal inactive.
	winc: Write increment signal. Used to trigger write operations.
	rinc: Read increment signal. Used to trigger read operations.
	wdata: Write data input. The width [WIDTH-1:0] is configurable and represents the data to be written into the FIFO.

Output ports:
wfull: Write full signal. Indicates if the FIFO is full and cannot accept further write operations.
rempty: Read empty signal. Indicates if the FIFO is empty and cannot provide any data for read operations.
rdata: Read data output. The width [WIDTH-1:0] is configurable and represents the data read from the FIFO.

Parameter:
	WIDTH = 8
	DEPTH = 16

Implementation:
The module implements an asynchronous FIFO using a dual-port RAM module and additional logic for managing read and write pointers.
Dual-port RAM:
The module instantiates a dual-port RAM module named "dual_port_RAM" with configurable depth and width.
The RAM module has separate clock inputs for write (wclk) and read (rclk) operations.
The RAM module has separate address inputs for write (waddr) and read (raddr) operations.
The RAM module has a write enable input (wenc) and a write data input (wdata).
The RAM module has a read enable input (renc) and a read data output (rdata).
The RAM module stores data in a two-dimensional array, RAM_MEM, with a size of DEPTH by WIDTH.
Write and Read Pointers:
The module includes logic to manage write and read pointers for asynchronous operation.
The write and read pointers are represented by binary registers, waddr_bin and raddr_bin, respectively.
The write and read pointers are incremented based on the write and read increment signals (winc and rinc), respectively.
The write pointer is incremented on the positive edge of the write clock (posedge wclk) and reset to 0 on write reset (~wrstn).
The read pointer is incremented on the positive edge of the read clock (posedge rclk) and reset to 0 on read reset (~rrstn).
Gray Code Conversion:
The write and read pointers are converted to Gray code using XOR operations with right-shifted values.
The converted write and read pointers are stored in registers wptr and rptr, respectively.
The Gray code conversion reduces glitches and ensures proper synchronization of the write and read pointers.
Pointer Buffers:
The module includes buffer registers (wptr_buff and rptr_buff) to hold the previous values of the write and read pointers.
The buffer registers are updated on the positive edge of the respective clocks and reset to 0 on the respective resets (~wrstn and ~rrstn).
The buffer registers are used to synchronize the write and read pointers for determining the full and empty conditions.
Full and Empty Signals:
The module compares the current write and read pointers (wptr and rptr_syn) to determine if the FIFO is full or empty.
The wfull output is set to 1 when the write pointer is equal to the bitwise negation of the most significant bit of the read pointer concatenated with the remaining bits of the read pointer.
The rempty output is set to 1 when the read pointer is equal to the write pointer.
Input and Output Connections:
The module connects the input and output signals to the dual-port RAM module based on the control signals and pointer values.
The wen and ren signals control the write and read enable signals of the RAM module, respectively.
The wdata input is connected to the write data input (wdata) of the RAM module.
The rdata output is connected to the read data output (rdata) of the RAM module.

Explicit benchmark revision: FIFO parameter domain and Gray comparison (v2)

The original requirements above remain normative except for the two individually scoped benchmark corrections below. These corrections are benchmark data, not assumptions inferred by a generated candidate.

PB1 — Parameter-domain correction. The original clause "FIFO bit width and depth can be configured(parameter DEPTH = 16, parameter WIDTH = 8)" is amended as follows: WIDTH is a positive integer. The legal FIFO depths are DEPTH=2^A for an integer A>=0; non-power-of-two depths, including DEPTH=3, are explicitly outside this revised benchmark's supported parameter domain. DEPTH=1 is legal and is not excluded. The public parameter declaration order and defaults are WIDTH=8, DEPTH=16, ADDR_WIDTH=$clog2(DEPTH). ADDR_WIDTH is a derived public parameter and must equal A; an override is legal only when that equality holds. Pointer positions have A+1 bits and wrap modulo 2^(A+1). Storage selects the lower A binary bits; when A=0 the sole storage location is address zero. The supplied dual-port RAM behavior and its declared interface remain unchanged. Default operation remains a 16-word, 8-bit FIFO.

PB2 — Contradictory Gray-full comparison correction. The original sentence "The wfull output is set to 1 when the write pointer is equal to the bitwise negation of the most significant bit of the read pointer concatenated with the remaining bits of the read pointer." is superseded for the Gray-code full comparison only. For A>=1, the comparison target is the synchronized remote Gray position with its two highest bits A and A-1 complemented and every lower bit unchanged, consistently with the original introductory two-highest-bits rule. For the legal A=0 capacity-one case, the position is one bit and the comparison complements that sole bit. Equivalently the mask is 3<<(A-1) for A>=1 and 1 for A=0. The corresponding original introductory two-highest-bits sentence is restricted to A>=1; this explicit one-bit exception supplies its capacity-one extension. No other reset, clock, read-data, transaction or synchronizer requirements are removed by this correction.

Event convention: each table row drives the explicitly named clock levels and data, then observes settled outputs. The model must apply the edge described by those levels exactly once; it must not insert a second pipeline delay.

1. Module and ports


2. Reset
Both resets are asynchronous and active low. Assertion of wrstn immediately resets the write position and both receiving read-position samples to zero and publishes wfull=0. Assertion of rrstn immediately resets the read position and both receiving write-position samples to zero and publishes rempty=1. Each reset blocks only its corresponding transactions. Neither reset clears any stored word or rdata. Assertion takes precedence over a coincident corresponding rising edge. The opposite domain continues normally; its status does not change merely because the remote reset asserts.
Release itself neither advances a position nor publishes any output. The first subsequent write rising edge may accept a write using pre-edge wfull=0. The first subsequent read rising edge rejects a read using pre-edge rempty=1 and continues status reevaluation. Reassertion restarts the corresponding position and sampling epoch, retaining stored words and rdata; a read reset can therefore restart reading at address zero.
Before reset, wfull and rempty are hardware unknown; the no-reset, no-transfer power-up clock edges do not establish them. rdata starts hardware unknown and remains so until an accepted read supplies a defined word. Reading a never-written address publishes hardware unknown. This is certain-answer hardware behavior, not missing evidence. All stored data retain their initialization validity separately from their WIDTH-bit payload.
Implementation choice C1: the concrete finite instance retains the original model's zero initial position and receiving-sample payloads, with initial clock levels zero. Initial public flags remain hardware unknown as required by Q9, Q15, Q29 and Q30; transactions cannot be accepted on an unknown acceptance guard. This compatible initial-state completion does not claim source-derived hardware power-up initialization, require reset before use, or initialize RAM or rdata. Reset establishes the stated positions independently of this initial choice.

3. Timing
wfull is registered in the write domain; rempty is registered in the read domain. Each updates immediately after its corresponding non-reset positive clock edge, using the updated local transaction position and the remote sample from immediately before the second preceding receiving positive edge. Missing samples in the current receiving-reset epoch are zero. Each holds between its edges except for its own asynchronous reset. Status reevaluation continues with increment disabled and with a rejected request.
For a remote position change at E0, E1 is the first receiving rising edge whose pre-edge sample includes that change; a coincident receiving edge at E0 cannot include it. With the remote position stable afterward, post-edge E1 and E2 still compare the old history, and post-edge E3 compares the new history. Pre-edge E3 still observes the E2 flag; pre-edge E4 observes the E3 flag. These are three receiving edges, not three edges of the remote clock. Stopping the receiving clock pauses this progression, and resuming continues it.
rdata is registered: an accepted read at E0 publishes the pre-edge stored word immediately after E0, with zero additional read-clock cycles of latency. It holds through E1 and all later events until another accepted read. There is no completion pulse or separate ready phase. Continuous eligible reads publish one word on each positive rclk edge.
Falling edges and steady clock levels neither accept transactions nor publish status or data. The clocks are independent; no period, duty cycle or relationship is specified.
The normative finite trace uses WIDTH=8, DEPTH=16, ADDR_WIDTH=4 and half-cycle clock-level inputs. Each row observes the pre-edge public values, with any currently asserted asynchronous reset already settled, then commits the pending positive-edge transition once. Thus a row containing a rising clock still displays the previous registered result, and a subsequent row displays that edge's publication. Reset assertion represented by a low reset input resets state in that transition even without a clock edge; release retains that state. Rows are interface observations, not an inferred 10 ns clock period; no step_ns or sample_offset_ns value is supplied in this interface. This finite scenario does not prescribe the circuit's independent clock periods or limit its asynchronous reset pulses.

4. Behaviour
The retained original requirements, including PB1 and PB2, remain normative. No supplied submodule definition exists to reproduce. The required configurable dual-port RAM submodule and its source-declared interface remain required, as do the binary positions, registered Gray positions, previous-position buffers and two-stage cross-domain pointer synchronization described in the source. The mathematical histories below describe behavior rather than replacing those source obligations.
For positive integer WIDTH and DEPTH=2^A, A>=0, ADDR_WIDTH=A, both positions wrap modulo 2*DEPTH. Address selection is the low A binary bits, or address zero when A=0. The position Gray representation is binary XOR binary shifted right by one, in A+1 unsigned bits. For A>=1, full Gray comparison complements the two highest remote bits; for A=0 it complements the sole bit. All lower bits remain unchanged. PB1 and PB2 are explicit benchmark amendments already present in the retained source, not inferred parameter restrictions. The public parameter family includes capacity one.
A write is accepted only on posedge wclk with wrstn=1, winc=1 and pre-edge wfull=0; a read is accepted only on posedge rclk with rrstn=1, rinc=1 and pre-edge rempty=0.
An accepted write stores all WIDTH bits of the sampled wdata at the pre-edge write position modulo DEPTH and advances that position by one modulo 2*DEPTH.
An accepted read publishes the pre-edge word at the pre-edge read position modulo DEPTH and advances that position by one modulo 2*DEPTH; a simultaneous same-address write supplies the old word to the read.
After each non-reset write rising edge, wfull is one exactly when the post-edge write position equals the sampled remote read position plus DEPTH modulo 2*DEPTH; otherwise it is zero.
After each non-reset read rising edge, rempty is one exactly when the post-edge read position equals the sampled remote write position; otherwise it is zero.
Coincident clock edges use pre-edge histories and independent pre-edge acceptance guards. A simultaneous read cannot bypass full rejection, and a simultaneous write cannot bypass empty rejection. The clearing edge still rejects a request if its pre-edge flag prohibited acceptance; the next eligible edge can resume transactions. Filling or consuming the last visible word publishes the corresponding blocking flag after that accepting edge.
Holding winc high permits one write at every eligible write rising edge; holding rinc high permits one read at every eligible read rising edge. Disabled enables pause their transactions without undoing data or halting status reevaluation. Reset or blocked requests do not advance their corresponding position. Requests resume when the pre-edge status permits acceptance.
wdata affects memory only on an accepted write, preserves bit i as bit i, and never affects status; changes between edges, during write reset, while full or with winc=0 have no write effect.
rdata retains its last published word across rejected reads, disabled enables, writes alone, either reset assertion or release, falling edges and stopped clocks.
wrstn asynchronously restarts only the write position and its receiving-sample epoch and forces wfull=0; it retains memory and rdata and does not directly reset read-domain progress.
rrstn asynchronously restarts only the read position and its receiving-sample epoch and forces rempty=1; it retains memory and rdata and does not directly reset write-domain progress.
wclk accepts writes and reevaluates wfull only at positive edges, while asynchronous wrstn remains effective during a stopped clock.
rclk accepts reads and reevaluates rempty only at positive edges, while asynchronous rrstn remains effective during a stopped clock.
All one-bit input encodings are covered by these levels and edge laws; data spans every WIDTH-bit pattern. No additional mandatory reset sequence, warm-up interval, overlap exclusion or input restriction is imposed.
