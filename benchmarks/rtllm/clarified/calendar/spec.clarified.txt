Module and integration contract

Module: calendar.
Ports below are in exact declaration order:
- CLK: input 1 bit.
- RST: input 1 bit.
- Hours: output [5:0].
- Mins: output [5:0].
- Secs: output [5:0].

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

1. Module and ports



3. Reset

RST is active high and asynchronous: asserting it immediately makes Hours, Mins, and Secs zero, with priority over a simultaneous rising edge of CLK. They remain zero throughout assertion, including across any number of CLK edges. Deasserting RST causes no immediate change. On the first subsequent rising edge of CLK, normal counting applies to the retained reset values: immediately after that edge Secs is 1, while Mins and Hours remain 0.

At power-up, before any reset edge has been seen, Hours, Mins, and Secs are all 0, the same values produced by reset. The complete state consists of the current hour, minute, and second counts, all of which are zero both at power-up and whenever reset is asserted.

4. Timing

Hours, Mins, and Secs are registered outputs. Each changes immediately after an applicable rising edge of CLK and otherwise retains its value, except that asynchronous reset can clear it immediately. An edge uses the values present immediately before that edge. Thus the updated value has one rising-edge transition of latency from those pre-edge values and is visible after that same edge. There are no completion pulses, busy intervals, or disabled transaction intervals; every rising edge is immediately eligible to apply the laws below.

A steady CLK level and a falling CLK edge have no effect. With RST high, rising edges also leave all outputs at zero. Measured in CLK rising-edge cycles with RST low, the complete Secs value sequence has period 60 cycles, the complete Mins value sequence has period 3,600 cycles, and the complete Hours value sequence has period 86,400 cycles. Duty cycle is not applicable to these multibit count outputs. No physical CLK period or propagation delay is specified.

For the evaluated full-cycle trace, row k denotes the settled observation at k full-cycle steps from the start of its stimulus block. Each row samples outputs before that row's transition, and the resulting state is observed on the next row. This observation convention is separate from the circuit law above and does not imply a 10 ns clock tick or any other physical duration.

5. Behaviour

RST has priority over all counting. For either value of CLK, RST high makes every output zero and holds it there. Releasing RST while CLK is steady or falling changes nothing. With RST low, only a rising edge advances the calendar, and repeated rising edges apply the same rules continuously without cancellation, interruption, or a completion state.

With RST low, Secs updates just after every rising edge, wrapping from 59 to 0 and otherwise incrementing by one.

With RST low, Mins updates just after a rising edge only when pre-edge Secs is 59: it wraps from 59 to 0 and otherwise increments by one; on every other edge it retains its value.

With RST low, Hours updates just after a rising edge only when the pre-edge Mins and Secs are both 59: it wraps from 23 to 0 and otherwise increments by one; on every other edge it retains its value.

All three decisions use the same pre-edge values. Consequently, 23:59:59 becomes 00:00:00 on one rising edge. The reachable output ranges are Hours 0 through 23 and Mins and Secs 0 through 59. Since there are no data inputs or command inputs, CLK and RST exhaust the input cases the module can receive.
