Module and integration contract

Module: edge_detect.
Ports below are in exact declaration order:
- clk: input 1 bit.
- rst_n: input 1 bit.
- a: input 1 bit.
- rise: output 1 bit.
- down: output 1 bit.

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

1. Module and ports.



3. Reset.

Reset `rst_n` is active low and asynchronous. Whenever `rst_n` is low, `rise` and `down` are both 0 independently of `a` and clock activity. Assertion has priority over a simultaneous rising edge, establishes the preceding sampled value of `a` as 0, clears both result pulses, and remaining in reset retains that state. Releasing reset changes neither output by itself: both remain 0 until a subsequent rising edge performs a comparison. On the first rising edge after release, `a = 1` produces `rise = 1` and `down = 0`, while `a = 0` produces `rise = 0` and `down = 1`.

At power-up before reset has ever been asserted and before any rising edge has occurred, both outputs are unknown. The implementation must leave their stored state uninitialised, with no initial block or declaration initialiser. If a rising edge occurs before any reset, that edge establishes the first sampled history value and leaves both outputs 0; later rising edges compare against that sample.

4. Timing.

`a` is sampled only on each rising edge of `clk` while `rst_n` is high. `rise` and `down` are registered outputs: a transition sampled at a rising edge becomes visible immediately after that edge and is represented in the following pre-edge observation row. Each asserted indication lasts exactly one clock interval. At every later rising edge it is cleared unless that edge detects a new corresponding transition. A steady clock level and falling edges do not sample `a` or update either output. Changes of `a` between rising edges have no immediate effect.

The Lean trace uses a full-cycle timebase: row k observes the settled outputs immediately before modeled rising edge k, and the transition computed at that edge appears in row k+1. The interface supplies no `step_ns` or `sample_offset_ns`, so the trace establishes no physical clock period or propagation delay in nanoseconds.

5. Behaviour.

While `rst_n` is high, every rising edge samples the one-bit input `a` and compares it with the preceding sampled value. A preceding 0 followed by a sampled 1 sets `rise` to 1 and `down` to 0. A preceding 1 followed by a sampled 0 sets `down` to 1 and `rise` to 0. Two consecutive samples of 0 or two consecutive samples of 1 set both outputs to 0. The current sample becomes the preceding sample for the next rising edge, so every rising edge starts a fresh comparison and repeated transactions are handled without an idle-cycle requirement.

Reset makes `a` inactive and records a preceding sample of 0. Reset assertion asynchronously makes both public outputs 0, and reset release alone retains those values. The first rising edge after release is a specified special case: it sets `rise` exactly when `a` is 1 and sets `down` exactly when `a` is 0. From the second rising edge onward, the ordinary transition comparison law applies.
