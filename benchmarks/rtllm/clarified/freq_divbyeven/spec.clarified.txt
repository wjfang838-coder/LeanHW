Module: freq_divbyeven.

- clk: input 1 bit.
- rst_n: input 1 bit.
- clk_div: output 1 bit.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). 1. Module and ports.



3. Reset.

Reset is active low and asynchronous. Whenever rst_n is low, clk_div is immediately forced to 0 without waiting for a rising edge of clk, and the divide sequence is restarted. Continued low or repeated reset assertions retain clk_div at 0 and retain the restarted sequence. A reset assertion coincident with a rising edge has priority over that edge.

Before reset has ever been asserted, clk_div and the counter state are unknown. The implementation must leave both uninitialised, with no initial block and no declaration initialiser. On release of reset, clk_div remains 0; release alone causes no state change. On the first and second rising edges after release it remains 0, and on the third rising edge it toggles to 1. The counter state is 0 while reset is asserted, remains 0 on release, advances to 1 and then 2 on the first two rising edges after release, and returns to 0 on the third rising edge as clk_div toggles.

4. Timing.

clk_div is a registered periodic output with asynchronous reset. For the default NUM_DIV value of 6, its half-period is exactly 3 rising edges of clk and its full period is exactly 6 rising edges: 3 cycles low followed by 3 cycles high after the initial post-reset cadence reaches its first toggle. More generally, for each supported NUM_DIV value, clk_div toggles every NUM_DIV/2 rising edges, so its period is NUM_DIV cycles and its duty counts are NUM_DIV/2 low cycles and NUM_DIV/2 high cycles.

The evaluated object uses full-cycle sampling. Row k is the settled observation at k * step_ns according to the interface timing configuration, sampled at its configured sample_offset_ns, and is not based on an implicit 10 ns clock. Each row observes the state before that row's rising-edge transition; therefore, a toggle caused by row k's rising edge first appears in row k+1. This trace observation convention is separate from the circuit law above, whose period and delay are defined in rising-edge counts.

5. Behaviour.

The public parameter NUM_DIV defaults to 6. Supported configurations are the even integer values from 2 through 32 inclusive. Values outside that set are unsupported and their behavior is not specified.

While rst_n is high, only rising edges of clk advance the divide sequence. Static clk levels and falling edges have no effect. Starting from a restarted sequence, clk_div holds its current value for the first NUM_DIV/2 - 1 rising edges and toggles on the NUM_DIV/2-th rising edge; the sequence then restarts and repeats indefinitely, with no completion state. For the default NUM_DIV value of 6, clk_div holds on the first two rising edges and toggles on the third, repeating that three-rising-edge half-period cadence thereafter.

Driving rst_n low asynchronously forces clk_div to 0 and restarts the divide sequence. Deasserting rst_n alone has no effect. A later reset cancels any partial count immediately, clears clk_div, and causes the next toggle to occur on the NUM_DIV/2-th rising edge after reset is released. Repeated reset assertions and continued assertion do not advance the sequence. Reset has priority when asserted coincident with a rising edge.

clk_div is asynchronously cleared to 0 by reset, stays low on reset release, holds through the first NUM_DIV/2 - 1 post-reset rising edges, and toggles on the NUM_DIV/2-th and every NUM_DIV/2-th rising edge thereafter. For NUM_DIV=6, it holds through two post-reset rising edges and toggles on the third. Before the first reset assertion, clk_div remains unknown.
