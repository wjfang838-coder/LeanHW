Module and integration contract

Module: multi_pipe_8bit.
Ports below are in exact declaration order:
- clk: input 1 bit.
- rst_n: input 1 bit.
- mul_a: input [size-1:0].
- mul_b: input [size-1:0].
- mul_en_in: input 1 bit.
- mul_en_out: output 1 bit.
- mul_out: output [size*2-1:0].

Public parameters (preserve names, defaults and symbolic port ranges):
-  size: default = 8.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

Module and ports



Reset

rst_n is active low. Assertion is asynchronous and has priority over all clock activity. Whenever rst_n is low, mul_en_out is 0 and mul_out is 0, and every pending slot is cancelled.

Before reset has ever been asserted, both mul_en_out and mul_out are unknown. The implementation must leave their power-up state uninitialised, with no initial block or declaration initialiser that gives either output or its stored state a defined value.

After reset is released, both outputs remain 0 until a newly accepted slot completes the full pipeline latency. On the first rising edge after release, the current input slot is accepted; immediately before that edge the outputs are still 0. Reset cancellation leaves no earlier result to emerge after release.

Timing

Inputs are accepted on each rising edge of clk while rst_n is high. Falling edges and steady clock levels have no effect. Under the normative pre-edge observation convention, a slot accepted at the rising edge after row k produces its output at row k+3: the row immediately preceding the fourth rising edge when the capture edge is counted as the first. Thus mul_en_out and mul_out are registered outputs with three row-to-row clock transitions of latency from mul_en_in and the simultaneously sampled mul_a and mul_b.

Each accepted slot produces one corresponding output interval lasting one clock cycle. Consecutive accepted slots produce consecutive output intervals. This full-cycle trace convention does not assign a physical duration to a row: row k denotes k times the interface step duration after settling, independently of the circuit's clock period and propagation delays. The interface provides no numeric step duration or sampling offset, and the circuit's actual clock period and delays are not constrained by this specification.

Behaviour

While rst_n is high, each rising edge accepts the current enable and operands and advances every pending transaction once. Consecutive rising edges accept distinct consecutive slots, and reset has priority when active.

For a slot accepted with mul_en_in high, mul_a and mul_b are sampled together as unsigned size-bit values. At that slot's latency-aligned output interval, mul_en_out is 1 and mul_out is their unsigned product, represented in 2*size bits. Changes to either operand between rising edges or during a disabled slot do not affect an enabled product already accepted. Consecutive enabled operand pairs remain distinct.

For a slot accepted with mul_en_in low, the latency-aligned mul_en_out is 0 and mul_out is 0 regardless of mul_a and mul_b. Disabled slots do not retain an older product. Slots are independent, so enabled and disabled slots in any order, including repetitions of either, each yield their own latency-aligned output interval.

Driving rst_n low cancels every pending enabled or disabled slot. After release, new slots may be accepted on rising edges, but no cancelled output can later appear.

The concrete evaluated object samples the low 8 bits of each operand and produces the low 16 bits of their unsigned product, matching size=8. The public parameterized contract applies the same unsigned multiplication law at parameter size, with the product represented in the declared 2*size-bit output width.
