Module and integration contract

Module: pulse_detect.
Ports below are in exact declaration order:
- clk: input 1 bit.
- rst_n: input 1 bit.
- data_in: input 1 bit.
- data_out: output 1 bit.

Public parameters (preserve names, defaults and symbolic port ranges):
-  s0: default = 2'b00.
-  s1: default = 2'b01.
-  s2: default = 2'b10.
-  s3: default = 2'b11.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

1. Module and ports.



3. Reset.

rst_n is active low and asynchronous. Whenever rst_n is low, data_out is 0 immediately, independently of clk and data_in. Assertion clears the entire remembered input history and keeps that history empty through any rising clock edges while reset remains asserted; reset has priority if assertion coincides with a rising edge.

At power-up, before reset has ever been asserted, data_out is 0 for every data_in sequence. The remembered history initially contains no valid samples. No reset edge is required to establish the specified power-up value of data_out.

Releasing rst_n causes no capture or output assertion by itself. Before the first rising edge after release, data_out remains 0. That first rising edge captures one sample, leaving insufficient history for detection, so data_out remains 0 after it. A second rising edge establishes two post-reset samples; data_out can then respond to the current data_in according to the behaviour below.

4. Timing.

data_out is combinational with respect to current data_in and asynchronous reset. Its detection latency is zero clock cycles from the current data_in value once the two samples captured on the preceding rising edges are 0 then 1. Under the normative pre-edge observation convention, row k is sampled before rising edge k and therefore sees history captured only through the preceding rising edge; the capture performed by edge k is first reflected in the next row.

The Lean object uses a full-cycle timebase: successive rows are separated by one actual rising-edge-to-rising-edge clock period. If the test interface assigns step_ns and sample_offset_ns, row k denotes k * step_ns after settling, with sampling at the specified offset; this observation convention does not impose a 10 ns clock. The circuit itself has no specified numeric clock period or propagation delay.

For cycle-aligned input stimulus, each completed 010 occurrence is asserted in exactly the sampled row containing its final 0 and clears after the following rising edge changes the captured suffix. Electrically, data_out has no fixed cycle-width hold: it clears immediately whenever reset is asserted, current data_in becomes 1, or the captured suffix ceases to be 01. Overlapping occurrences may produce separate assertions.

5. Behaviour.

All input ports are one bit, so the cases below cover every encoding they can receive.

Whenever rst_n is 0, data_out is 0, data_in has no effect, and every rising edge leaves the remembered history empty.

With rst_n equal to 1, every rising edge captures data_in and advances the remembered two-sample suffix exactly once. Releasing reset, falling clock edges, and steady clock levels do not capture or advance the history. Repeated rising edges each advance it once. Reset assertion interrupts any partial or repeated detection, including when reset assertion coincides with a rising edge.

With rst_n high, data_out is 1 exactly when the currently applied data_in is 0 and the input history captured on preceding rising edges has 01 as its longest suffix; otherwise it is 0, so overlapping occurrences such as 01010 are each indicated on their final 0.

After reset and before two post-reset rising-edge samples have established a captured history ending in 01, data_out is 0 for either value of data_in. Once the captured suffix is 01, current data_in equal to 0 asserts data_out combinationally and current data_in equal to 1 deasserts it. There is no busy interval: continuous, repeated, and overlapping input sequences are all processed by the same law.
