Module and integration contract

Module: radix2_div.
Ports below are in exact declaration order:
- clk: input 1 bit.
- rst: input 1 bit.
- dividend: input [7:0].
- divisor: input [7:0].
- sign: input 1 bit.
- opn_valid: input 1 bit.
- res_valid: output 1 bit.
- res_ready: input 1 bit.
- result: output [15:0].

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

1. Module and ports



3. Reset

Reset is active high and synchronous to the rising edge of clk. On every rising edge for which rst is 1, reset has priority: it aborts any active operation, clears the pending completion state, sets res_valid to 0, and sets result to 16'h0000. Repeated asserted reset edges preserve those values. On the first rising edge after rst is released, normal request acceptance and operation progress resume; if no eligible request is present, all reset-state values remain unchanged.

Before the first rising edge with rst asserted has occurred, both res_valid and result are unknown. They remain unknown even if an operation is attempted in that interval. The implementation must leave their stored values uninitialised at power-up, with no initial block or declaration initialiser that assigns them definite values.

4. Timing

Only rising edges of clk change state or registered port behavior. Falling edges and stable clock levels have no effect. res_valid and result are registered outputs. Rows in the normative trace are sampled before the rising-edge transition: row k is the observation at k * step_ns after settling, using the interface's sample_offset_ns, and does not imply a 10 ns clock. This observation convention is separate from the circuit law that state changes only on rising clk edges.

An accepted request is followed by eight division-progress rising edges. Completion occurs on the ninth rising edge counting the request-capture edge, and the completed result and asserted res_valid are observable in the following row. res_valid is then continuously 1 until cleared by a rising edge with res_ready equal to 1, so its asserted duration is the number of cycles until response acceptance rather than a fixed pulse width. A response-acceptance edge makes res_valid 0 in the following row. result retains the completed value across response acceptance.

5. Behaviour

With rst equal to 0, a rising edge accepts a request exactly when opn_valid is 1, no operation is active, and res_valid is 0. The edge captures sign, dividend, and divisor. opn_valid equal to 0 has no effect. An assertion during reset, during an active operation, or while a result is outstanding is ignored. Holding or repeatedly asserting opn_valid starts another transaction only on a later eligible rising edge. Changes to sign, dividend, or divisor on any edge that does not accept a request have no effect on the current transaction.

For a captured sign value of 0, dividend and divisor are unsigned eight-bit operands. For a nonzero divisor, the completed value obeys result[15:8] = dividend % divisor and result[7:0] = dividend / divisor. Thus the remainder occupies the upper byte and the quotient occupies the lower byte, with each component truncated to eight bits.

For a captured sign value of 1, dividend and divisor are two's-complement signed eight-bit operands. Division uses their magnitudes; the quotient sign is the XOR of the captured operand sign bits, and the remainder sign is the captured dividend sign bit. Quotient and remainder are encoded independently as eight-bit two's-complement values and concatenated as result = {remainder, quotient}. This also defines the overflow case -128 / -1 as quotient 8'h80 and remainder 8'h00.

For a zero captured divisor, the completed quotient is 8'hff and the completed remainder is the captured dividend bit pattern, for result = {dividend, 8'hff}.

After reset, result is 16'h0000. During request processing it remains a determined registered value; this design retains the prior result until completion writes the new {remainder, quotient}. Completion asserts res_valid and writes result together. While res_ready is 0, both the completed result and res_valid are retained. A rising edge with res_ready equal to 1 clears res_valid but retains result. Reset overrides request capture, progress, completion, and response acceptance. A new request cannot be captured on the same edge that clears res_valid; it becomes eligible on a later rising edge.
