Module and integration contract

Module: traffic_light.
Ports below are in exact declaration order:
- rst_n: input 1 bit.
- clk: input 1 bit.
- pass_request: input 1 bit.
- clock: output [7:0].
- red: output 1 bit.
- yellow: output 1 bit.
- green: output 1 bit.

Public parameters (preserve names, defaults and symbolic port ranges):
-  idle: default = 2'd0.
-  s1_red: default = 2'd1.
-  s2_yellow: default = 2'd2.
-  s3_green: default = 2'd3.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

1. Module and ports



2. Reset

rst_n is an active-low asynchronous reset. Whenever rst_n is low, clock is 8'b00001010 and red, yellow, and green are all 0, regardless of clk or pass_request. Repeated or continued reset assertion retains those values, and reset assertion takes priority over a coincident rising clk edge and pass_request.

Before rst_n has ever been asserted low, clock, red, yellow, and green are unknown. The implementation must leave their corresponding stored state uninitialised: no initial block or declaration initialiser may give it a defined power-up value.

After reset is released, the pre-edge values remain clock=10 and all three lights=0. The first later rising clk edge enters the red interval; the next sampled row has clock=10, red=1, yellow=0, and green=0. No state advances merely because reset is released.

3. Timing

All four outputs represent registered state. rst_n can change their reset-visible values asynchronously. With rst_n high, only a rising edge of clk advances them; falling edges and steady clk levels have no effect. Each update is visible in the sampled row following that rising edge and is retained until the next rising edge or reset assertion.

The initial all-off interval lasts from reset through the first rising edge after release. Each red interval is 10 rising-edge countdown cycles with red asserted, each green interval is 60 rising-edge countdown cycles with green asserted unless shortened by an accepted pass_request, and each yellow interval is 5 rising-edge countdown cycles with yellow asserted. Each asserted light has a duty duration equal to its stated interval: red for 10 cycles, green for 60 cycles when unshortened, and yellow for 5 cycles. The complete repeating period is therefore 75 cycles when no green interval is shortened. An accepted request changes that period by reducing only the affected green interval.

Trace row k is the settled pre-edge observation at k times the interface's step_ns after settling, using its sample_offset_ns convention; this observation spacing is separate from the circuit's phase periods and one-rising-edge update laws.

4. Behaviour

The phase sequence after reset is initial all-off, red, green, yellow, then red, green, yellow repeatedly. Exactly one of red, yellow, and green is 1 in a timed phase. During red, red=1 and yellow=green=0. During green, green=1 and red=yellow=0. During yellow, yellow=1 and red=green=0.

rst_n is an active-low asynchronous reset: asserting it immediately makes clock 10 and all three light outputs 0, it overrides a simultaneous rising clk edge and pass_request, holding or repeatedly asserting it retains those values, and after release only later rising clk edges advance operation.

With rst_n high, only each rising clk edge advances the countdown and phase-output sequence, while falling edges and steady levels have no effect; with rst_n low, clk edges have no effect, and reset assertion overrides a simultaneous rising edge.

At a rising clk edge with rst_n high, pass_request forces clock to 10 only when green is 1 and the pre-edge clock value exceeds 10; it has no effect in other phases or at clock values at most 10, reset has priority, a pulse need not be retained, and a held or repeated request cannot retrigger until a later qualifying green interval.

clock is asynchronously 10 throughout reset; after reset release its pre-edge row remains 10 until the first rising edge, each rising edge then exposes either the normal modulo-256 decrement, a phase-start load of 60 for green, 5 for yellow, or 10 for red, or the higher-priority accepted-request value 10, and it retains that result between active edges until the next update or reset assertion.

red is asynchronously 0 during reset, remains 0 in the pre-edge row after release, becomes 1 as observed after the next rising edge and stays 1 for the red interval, then becomes 0 upon the transition to green and remains 0 through green and yellow before the sequence restarts.

yellow is asynchronously 0 during reset and remains 0 through the initial, red, and green intervals, becomes 1 as observed after the transition into yellow, stays 1 for that interval, then becomes 0 after the transition back to red and repeats this behavior each cycle.

green is asynchronously 0 during reset and remains 0 through the initial and red intervals, becomes 1 as observed after the transition into green, stays 1 for the full or request-shortened green interval, then becomes 0 after the transition to yellow and repeats this behavior each cycle.

At the end of a red interval, the next rising edge loads clock with 60 and begins green. At the end of green, the next rising edge loads 5 and begins yellow. At the end of yellow, the next rising edge loads 10 and begins red. A phase remains active through the pre-edge row in which clock is 2; the light changes only after the interval completes and the following phase is observed. The countdown arithmetic is unsigned eight-bit arithmetic, and a normal decrement is truncated at the explicit eight-bit counter-write boundary, giving modulo-256 behavior.

Every one-bit input is interpreted by its low bit. Thus all representable input values are covered: an even rst_n value asserts reset and an odd value releases it; an odd pass_request value is asserted and an even value is deasserted.
