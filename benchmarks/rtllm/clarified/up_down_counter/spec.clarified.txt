Module and integration contract

Module: up_down_counter.
Ports below are in exact declaration order:
- clk: input 1 bit.
- reset: input 1 bit.
- up_down: input 1 bit.
- count: output [15:0].

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

Module and ports.



Reset.

Reset is active high and synchronous to the rising edge of clk. At a rising edge where reset is high, count becomes 16'h0000 regardless of up_down; reset therefore has priority over counting. Merely asserting reset between rising edges does not change count. While reset remains high, every rising edge establishes or retains count at 16'h0000. Deasserting reset has no immediate effect. At the first rising edge after release, up_down selects the normal one-step modulo update from zero.

Before the first rising edge at which reset is asserted, count is unknown. The implementation must leave count's stored value uninitialised: it must not use an initial block or declaration initialiser to give it a defined power-up value. If rising edges occur before any reset edge, count remains unknown.

Timing.

Count is a registered output. A rising edge of clk samples reset and up_down. When reset is low and count has previously been established by reset, the selected update is visible immediately after that edge and is retained until the next rising edge. Thus the latency from the sampled up_down value to the updated count is one edge, represented as one full clock cycle between pre-edge trace rows. Count has no completion pulse and accepts an update on every rising edge.

The circuit's clock period and propagation delay are not specified. In the evaluated trace, row k is sampled before the active edge for modeled cycle k, after settling from earlier events; this observation convention does not assert a 10 ns clock or any other physical period.

Behaviour.

Each rising edge of clk is the only event that updates count; clk's low level and falling edges have no effect, and repeated rising edges repeatedly apply the selected operation.

When reset is high at a rising edge, count becomes 16'h0000 regardless of up_down, and reset has priority over the simultaneous counting request.

With reset low, up_down high at a rising edge increments count by one modulo 2^16, while up_down low decrements count by one modulo 2^16; changes to up_down between rising edges have no effect.

Accordingly, incrementing 16'hffff produces 16'h0000, and decrementing 16'h0000 produces 16'hffff. All additions and subtractions are unsigned 16-bit operations whose result is truncated at the count storage boundary to the low 16 bits.

Once count is established, it reflects each selected one-step modulo update after the rising edge and retains that value until a later rising edge updates or resets it; no separate completion interval prevents a following edge from updating it again.
