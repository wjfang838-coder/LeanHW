Module and integration contract

Module: width_8to16.
Ports below are in exact declaration order:
- clk: input 1 bit.
- rst_n: input 1 bit.
- valid_in: input 1 bit.
- data_in: input [7:0].
- valid_out: output 1 bit.
- data_out: output [15:0].

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

1. Module and ports



3. Reset

Reset is active low and asynchronous. Whenever rst_n is low, valid_out is 1'b0 and data_out is 16'h0000, regardless of valid_in and data_in. Reset cancels any incomplete pair, discards any byte presented concurrently with reset, and establishes an empty pair state. Holding reset low retains those output values.

At power-up, before reset has ever been asserted and before the first active clock edge, valid_out and data_out are unknown. The implementation must leave both uninitialised: no initial block or declaration initialiser may define them. After reset is asserted, both outputs take their reset values immediately. After reset is released, those values remain unchanged until clocked behavior changes them: the first accepted byte leaves valid_out low and data_out unchanged, and the second accepted byte produces the first result and completion pulse.

4. Timing

The active clock edge is the rising edge of clk. Reset assertion acts asynchronously and independently of clk. All non-reset state changes are registered. A byte is accepted only on a rising edge with rst_n high and valid_in high.

valid_out is a registered one-cycle pulse. It becomes 1'b1 immediately after the rising edge that accepts the second byte of a pair and becomes 1'b0 immediately after the next rising edge unless that edge itself completes a pair. In the evaluated full-cycle trace, inputs in row k act at the edge after that row is sampled, so a completion caused by row k is first observed in row k+1.

data_out is registered. It updates immediately after the rising edge accepting the second byte, so the completed value is first observed in the next pre-edge row, and it otherwise retains its value until another completion or reset.

The concrete trace uses the interface timing values timing.step_ns and timing.sample_offset_ns. After settling, row k denotes k * timing.step_ns, with sampling at the interface's timing.sample_offset_ns; this observation convention does not impose an implicit 10 ns clock period. The circuit law is one active rising edge per full-cycle step, independently of the numeric trace cadence.

5. Behaviour

With rst_n high, valid_in equal to 1 at a rising edge accepts data_in. Accepted bytes alternate between the first and second byte of a pair. The first accepted byte begins a pair and is retained for that pair; it leaves valid_out low and does not change data_out. The second accepted byte completes the pair, sets data_out = {first accepted byte, second accepted byte}, with the earlier byte in data_out[15:8] and the later byte in data_out[7:0], and makes valid_out high for the following cycle.

With rst_n high, valid_in equal to 0 at a rising edge accepts nothing, preserves any incomplete pair, leaves data_out unchanged, and makes valid_out low after that edge. Because valid_in is one bit, these two values cover every encoding. Consecutive cycles with valid_in high accept consecutive bytes and complete a pair on every second accepted edge. Idle cycles between accepted bytes do not alter the saved first byte.

data_in affects a transaction only when sampled with valid_in high on a rising edge while rst_n is high. Values of data_in during reset, while valid_in is low, or between rising edges have no effect. All 256 data_in encodings are accepted without signed interpretation or arithmetic conversion; concatenation preserves both eight-bit patterns exactly.

Asserting rst_n low immediately sets valid_out to 1'b0 and data_out to 16'h0000, cancels any incomplete pair, and ignores valid_in and data_in even if assertion coincides with a rising edge. After release, the next accepted byte is the first byte of a new pair. A completed data_out value is retained through idle cycles and first-byte acceptance until another pair completes or reset is asserted.
