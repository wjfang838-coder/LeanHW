Module and integration contract

Module: TopModule.
Ports below are in exact declaration order:
- a: input 1 bit.
- b: input 1 bit.
- c: input 1 bit.
- out: output 1 bit.

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

1. Module and ports.



3. Reset.

The module has no reset input and no state elements. At power-up, including before any hypothetical reset edge, out is the combinational OR of the current a, b, and c inputs. There is no uninitialised interval, reset assertion behavior, or first step after reset release.

4. Timing.

out is combinational from a, b, and c with zero clock-cycle capture-to-observation latency. The module has no clock, registered output, pulse, or periodic signal, so it has no circuit period or duty cycle.

The evaluated trace uses the interface's full-cycle row convention only to order settled observations: each row observes the current inputs and their combinational output before the trace advances to the next stimulus. This observation convention does not impose a clock tick, circuit period, or propagation delay. The interface specifies no numeric step_ns or sample_offset_ns value.

5. Behaviour.

At all times, a contributes directly to out by logical OR with b and c: if a is 1, out is 1 regardless of b and c; if a is 0, out equals b OR c.

At all times, b contributes directly to out by logical OR with a and c: if b is 1, out is 1 regardless of a and c; if b is 0, out equals a OR c.

At all times, c contributes directly to out by logical OR with a and b: if c is 1, out is 1 regardless of a and b; if c is 0, out equals a OR b.

out is continuously a OR b OR c for every one-bit input combination, including simultaneous or repeated input changes. Thus out is 0 only for a = 0, b = 0, c = 0, and out is 1 for every other input combination. There are no modes, transactions, disabled inputs, cancellation, retained data, completion state, or restart behavior.
