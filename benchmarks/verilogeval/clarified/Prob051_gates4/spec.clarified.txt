Module and integration contract

Module: TopModule.
Ports below are in exact declaration order:
- in: input [3:0].
- out_and: output 1 bit.
- out_or: output 1 bit.
- out_xor: output 1 bit.

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

Module and ports



Reset

The module has no reset input and no reset behavior. It has no stored state. From power-up onward, including before any hypothetical edge, every output is defined by the current `in` value as stated below; no output has an uninitialized or unknown interval.

Timing

All three outputs are combinational functions of the current `in` value. Each has zero clock-cycle latency. There are no output pulses, periodic signals, active edges, capture events, or completion events.

For the evaluated SpecIR trace, row k is the settled observation at k times `timing.step_ns`, with the interface's `timing.sample_offset_ns`; this observation convention does not create a clock, period, delay, or state transition in the circuit. The supplied interface records no numeric `step_ns` or `sample_offset_ns`, so this document does not invent either value.

Behaviour

Only the low four bits represented by the 4-bit input port `in` participate in the following laws.

In every condition, the current value of `in` continuously determines all three outputs: `out_and` is the AND reduction, `out_or` is the OR reduction, and `out_xor` is the XOR reduction. There is no inactive level, mode, edge, interruption, transaction boundary, initialization interval, latency, hold interval, clear interval, completion event, or restart. Simultaneous and repeated input changes therefore produce the functions of the new current value.

`out_and` continuously equals 1 exactly when all four current bits of `in` are 1, and equals 0 otherwise.

`out_or` continuously equals 1 exactly when at least one of the four current bits of `in` is 1, and equals 0 otherwise.

`out_xor` continuously equals 1 exactly when an odd number of the four current bits of `in` are 1, and equals 0 when that number is even.

These laws cover every one of the 16 possible encodings of `in`.
