Module and integration contract

Module: TopModule.
Ports below are in exact declaration order:
- clk: input 1 bit.
- j: input 1 bit.
- k: input 1 bit.
- Q: output 1 bit.

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

Module and ports



Reset

There is no reset input and no reset operation, so reset polarity, reset synchronization, and a first step after reset release do not apply. At power-up, before any rising edge has assigned it, Q is unknown. The implementation must leave Q uninitialised, with no initial block or declaration initialiser. On the first rising edge, j=0 and k=1 makes Q 0, and j=1 and k=0 makes Q 1. With j=k=0, the unknown value is retained; with j=k=1, complementing the unknown value leaves it unknown.

Timing

Q is registered. The inputs j and k are sampled only on each rising edge of clk, and the resulting value of Q is observable after that edge and held until the next rising edge. Thus the latency from the sampled j and k values to the updated Q is one active edge: a normative trace row samples the old Q before its row's active edge, and that edge's result appears in the following row.

The concrete object uses full-cycle sampling. Row k denotes k times the interface step duration after settling; this observation convention is separate from the circuit law that state changes only on rising edges. A steady clk level, a falling edge, or changes to j or k between rising edges do not change Q. There are no pulse or periodic output signals.

Behaviour

Only a rising edge of clk affects Q: at each such edge, including consecutive edges, Q takes `(j & ~Q) | (~k & Q)` from the values immediately before that edge, while a steady clk level and falling edges have no effect and changes of j or k between rising edges neither interrupt nor alter the held output.

The value of j is sampled only on each rising edge of clk: with k=0, j=0 holds Q and j=1 sets Q to 1; with k=1, j=0 clears Q to 0 and j=1 complements Q, with the rule reapplied independently on every rising edge and changes between edges having no effect.

The value of k is sampled only on each rising edge of clk: with j=0, k=0 holds Q and k=1 clears Q to 0; with j=1, k=0 sets Q to 1 and k=1 complements Q, with the rule reapplied independently on every rising edge and changes between edges having no effect.

Q has no reset or specified power-up value; every rising edge of clk computes the new Q as `(j & ~Q) | (~k & Q)` from the pre-edge values, the result is observable after that edge and held until the next rising edge, so a table row sampled before an active edge shows the preceding value and that edge's result first appears in the following row, with no separate clear, completion, interruption, or restart interval.

Since j and k are one-bit ports, the four combinations above cover every input encoding.
