Module and integration contract

Module: TopModule.
Ports below are in exact declaration order:
- clk: input 1 bit.
- reset: input 1 bit.
- q: output [4:0].

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

1. Module and ports



3. Reset

reset is active high and synchronous to the rising edge of clk. At every rising edge at which reset is sampled high, q is set to 5'b00001; this reset action has priority over LFSR progression. Consecutive rising edges that sample reset high repeatedly set q to 5'b00001. Changes of reset between rising edges do not affect q. Releasing reset does not itself change q; at the first later rising edge that samples reset low, one progression step is applied to the current value, and that new value is retained until another rising edge.

At power-up, before any rising edge has assigned q, q is unknown. Merely asserting reset without a rising edge does not determine it. The implementation must leave q uninitialised in that interval, with no initial assignment or declaration initialiser. There are no state elements other than the five stored bits represented by q.

4. Timing

q is a registered output updated only on a rising edge of clk. A full-cycle trace row samples q before that row's rising-edge transition; consequently, the effect of a reset or progression edge appears in the following row. q holds its value at low and high clock levels and across falling edges. The interface's full-cycle observation convention means row k denotes k full-cycle steps after settling. No physical clock period in nanoseconds and no propagation delay are specified; those implementation timing quantities are distinct from the trace observation cadence.

reset-to-q latency is one trace row under this pre-edge convention: a reset value sampled at a rising edge is observed as 5'b00001 in the next row. Progression has the same one-row observation latency from its rising edge. q is neither a pulse nor a completion indication. The LFSR sequence has a period of 31 rising-edge progression cycles when reset remains low, and each state is held for one complete cycle; no separate duty-cycle requirement applies to this multi-bit state output.

5. Behaviour

Before the first rising edge assigns q, q is unknown, and merely setting reset without such an edge does not determine it.

On every rising edge, reset has priority. If reset is high, q becomes 5'b00001. If reset is low and q has previously been assigned, q changes from q[4:0] to {q[0], q[4], q[3] ^ q[0], q[2], q[1]}. This law applies to every possible 5-bit value of q, including 5'b00000; zero maps to zero. For the reset-seeded nonzero sequence, the recurrence visits all 31 nonzero 5-bit states before repeating and never reaches zero.

Only a rising edge of clk affects q: at every such edge reset has priority and selects 5'b00001, otherwise the stated recurrence is applied once to the current q; low levels, high levels, and falling edges have no effect, and repeated rising edges repeat this choice without any busy, interruption, or transaction state.

reset is synchronous and active high: its sampled high value at any rising clk edge sets q to 5'b00001 with priority over progression, its low value permits one progression step, changes between rising edges have no effect, consecutive sampled assertions repeatedly set the same value, and release takes effect only when sampled at a later rising edge.

q is initially unknown, is updated only by a rising clk edge, and is observed in a pre-edge row at its value from the preceding rising edge, so a sampled reset assertion becomes visible in the following row as 5'b00001 and the first post-release progression likewise becomes visible one row after its capture edge; q holds between edges and progression then continues on every rising edge with no separate clear, completion, or restart interval.

There are no disabled, busy, completion, cancellation, or transaction modes. Every rising edge independently performs the reset-or-progress choice above. A newly reset value is the first definite result; repeated reset assertions retain that reset value, and repeated low-reset rising edges continue progression without pausing.
