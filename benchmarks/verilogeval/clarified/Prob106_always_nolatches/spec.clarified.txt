Module and integration contract

Module: TopModule.
Ports below are in exact declaration order:
- scancode: input [15:0].
- left: output 1 bit.
- down: output 1 bit.
- right: output 1 bit.
- up: output 1 bit.

Public parameters (preserve names, defaults and symbolic port ranges):
- None.

Event convention: row k drives input i[k], waits for combinational settling and observes out(s[k], i[k]) BEFORE the active clock edge specified by the behavioral rules below. Use those rules for clock polarity and reset sensitivity. That edge produces s[k+1] = step(s[k], i[k]). A register assigned input i[k] at that edge is visible in row k+1; this is ONE register, not an input register plus an output register. Asynchronous reset assertion takes effect without waiting for that edge. Describe transaction latency from the accepting edge, and distinguish the completion pulse from the interval during which result data remains valid.

Module and ports



Reset

There is no reset input and no reset behavior. The design has no state elements. At power-up, before any edge or reset event, each output already has the definite combinational value selected by the current settled scancode: left, down, right, and up are each either 0 or 1 according to the behavior below. No output is uninitialized or unknown, and a first step does not change this rule.

Timing

Each of left, down, right, and up is combinational with zero clock-cycle latency from scancode. A change, interruption, or repetition of scancode affects all four outputs immediately after combinational settling. There are no pulses, periodic signals, clocked state transitions, transaction phases, or retained results. Trace row k is an observation after settling at the interface-defined time for row k; this observation convention does not imply a 10 ns clock, and the circuit has no actual period or delay law.

Behaviour

At all times, scancode 16'he06b asserts only left, 16'he072 asserts only down, 16'he074 asserts only right, and 16'he075 asserts only up, while every other scancode value deasserts all four outputs; a change, interruption, or repeated value has this same immediate combinational effect, and no simultaneous events or retained transaction state exist for this single encoded input.

left is continuously 1 exactly while scancode equals 16'he06b and is otherwise 0, with no reset, capture, completion, hold, clear, or restart phase; therefore a pre-edge row observes the value determined by the then-current settled scancode and there is no edge-to-observation latency.

down is continuously 1 exactly while scancode equals 16'he072 and is otherwise 0, with no reset, capture, completion, hold, clear, or restart phase; therefore a pre-edge row observes the value determined by the then-current settled scancode and there is no edge-to-observation latency.

right is continuously 1 exactly while scancode equals 16'he074 and is otherwise 0, with no reset, capture, completion, hold, clear, or restart phase; therefore a pre-edge row observes the value determined by the then-current settled scancode and there is no edge-to-observation latency.

up is continuously 1 exactly while scancode equals 16'he075 and is otherwise 0, with no reset, capture, completion, hold, clear, or restart phase; therefore a pre-edge row observes the value determined by the then-current settled scancode and there is no edge-to-observation latency.

Thus the complete behavior for all 65,536 possible 16-bit input encodings is specified: the four listed encodings produce their respective one-hot output, and all remaining encodings produce left = 0, down = 0, right = 0, and up = 0.
